# Проверка ответа перед отправкой

Дешёвая модель иногда вставляет в русский ответ английское слово, китайский иероглиф или придумывает ссылку, которой
нигде не было. Человек видит «Отличный progress!» или адрес несуществующей страницы. Проверка исправляет такие части ответа; в режиме `hold` исходный текст не показывается.

Как работает: агент закончил ответ — служба чата прогоняет каждую видимую текстовую часть через проверки по очереди, включая фразы перед вызовами инструментов. Проверка нашла
ошибку — просит ту же модель переписать текст. Исправленный текст записывается в чат и уходит человеку.

Работает в любом приложении, сценарий не нужен. Без настройки ничего не меняется: ход побайтно прежний.

## Подключение

```bash
pnpm add @ykurilov/agent-chat-reply-check
```

```ts
import { foreignWords, unknownLinks } from "@ykurilov/agent-chat-reply-check";

createChatServer({
  …,
  replyChecks: [
    foreignWords({ script: "cyrillic", knownNames: ["Excel", "Telegram"] }),
    unknownLinks({ appDomains: ["apps.example.com"] }),
  ],
});
```

То же поле есть у `createChatService`.

## Две готовые проверки

**Чужие слова** (`foreignWords`). Ищет иероглифы и другие письменности, латиницу в русском ответе (или кириллицу в
английском), латинскую букву внутри русского слова. Не трогает:

- слова, которые агент видел: инструкция, сценарий, реплики человека;
- названия из `knownNames`;
- сокращения из заглавных («CRM») и названия с большой буквы посреди фразы.

Переписанный текст сильно длиннее или короче исходного не принимается. Не вышло — уходит вариант с меньшим числом
чужих слов.

**Выдуманные ссылки** (`unknownLinks`). Находит адреса, которых агент нигде не видел. Человек написал «sveta-nails» —
адрес `sveta-nails.apps.example.com` законный, если домен приложений задан в `appDomains`. Одна переписка, остаток вырезается
кодом.

Ответ был целиком выдуманной ссылкой — после вырезания ничего не осталось. Тогда уходит запасная фраза «Ссылку здесь
дать не могу. Расскажите, что вы ищете, и я подскажу.», а в журнал — «запасная фраза». Свои слова — `labels`:

```ts
import { englishReplyCheckLabels, unknownLinks } from "@ykurilov/agent-chat-reply-check";

unknownLinks({ labels: englishReplyCheckLabels }); // или { linkOnlyReply: "…" }
```

Подробности настроек — в [README пакета](../packages/reply-check/README.md).

## Где работает

- **Веб-чат.** Ответ печатается по словам, а проверка идёт по готовому. Два режима:
  - `replace` (по умолчанию) — печатать как обычно, а исправленный текст заменяет напечатанный;
  - `hold` — не печатать до проверки: человек видит «печатает…», потом ответ целиком. С первого текста также задерживаются последующие события потока, включая карточки инструментов. Временные команды клиенту (`browserTools`, уведомления об изменении данных) идут сразу, чтобы не блокировать выполнение. Сами инструменты выполняются без ожидания проверки.

  ```ts
  replyChecks: { checks: [foreignWords({ script: "cyrillic" })], web: "hold" }
  ```

- **Мессенджеры** получают только проверенный текст: по словам ответ не шлётся.
- **Агент пишет первым** (сценарии, касания) — тоже через проверку: канал приложения получает готовый текст.

## Части ответа, поток и кэш

С 0.97.1 проверяется каждая текстовая часть успешно законченного хода (`complete`), по порядку. Часть перед
инструментом проверяется и тогда, когда после инструмента текста нет. Рассуждения, входы/результаты инструментов
и другие данные не переписываются. Остановленные, ошибочные и ожидающие ответа человека ходы, как и готовый
`beforeTurn.reply`, сохраняют прежнее поведение: эти проверки не запускаются.

В режиме `replace` исходная фраза успевает появиться на экране. После проверки поток передаёт `data-reply-text`
с `{ index, text }`, где `index` - номер текстовой части среди оставшихся после сбросов шагов, начиная с нуля.
React SDK применяет замену через `withoutResetSteps`, не удаляя карточки инструментов и не меняя их id.
Своя лента на сырых UI-частях должна использовать эту функцию из core/react. Отметка замены не сохраняется в БД:
там лежит уже исправленный текст. Обновляйте сервер и браузер одной версией SDK.

Проверки идут после генерации, без повторного запуска инструментов и шагов основного агента. Для каждой части
сохраняются прежние правила переписки, запасного результата, ошибок и учёта `answer_correction`; частей с ошибкой
может быть несколько, поэтому число переписок может вырасти. `knownTexts` читается один раз на проверяемый ход,
одинаковый список виденных текстов передаётся проверкам всех частей.

Запросы основного агента внутри текущего хода не меняются. Переписка проверки - отдельный запрос с прежней
инструкцией проверки и переменным текстом после неё. Следующий ход получает исправленную историю. Если ранняя
часть изменилась, кэш провайдера после места этой правки может не совпасть; сохранение кэша всего следующего
запроса не гарантируется.

## Как обновить приложение

Обновите установленные пакеты `@ykurilov/agent-chat-*` до одной версии 0.97.1 или новее, сервер и клиент вместе.
Настройка `replyChecks` и `foreignWords` не меняется. Своя проверка теперь вызывается для каждой видимой текстовой
части; если она ведёт счёт вызовов, учитывайте эту кратность. `service.checkReply` по-прежнему проверяет один
переданный текст. Миграций БД нет; код приложения менять не требуется для штатной ленты.

## Своя проверка

Проверка — функция. Вернула `{ text }` — текст заменяется. Ничего не вернула — текст подходит.

```ts
import type { ReplyCheck } from "@ykurilov/agent-chat-core";

const noPrices: ReplyCheck = async ({ text, rewrite }) => {
  if (!/\d+\s*₽/.test(text)) return;
  const fixed = await rewrite("Убери из ответа цены, остальное не меняй.", text);
  return { text: fixed, note: "цены убраны" };
};
```

- `seenTexts` — что агент видел за ход, плюс тексты приложения (`knownTexts`). Свои прошлые ответы агента туда не входят,
  как и служебные сообщения приложения (см. «Что считается виденным»).
- `rewrite(system, prompt)` — переписать моделью хода без рассуждений.
- `note` уходит в журнал.
- Проверка упала или вернула пустой текст — остаётся текст до неё, строка в `logError`.

## Что считается виденным

`seenTexts` — слова и ссылки, которые проверки считают законными:

- инструкция чата, блоки контекста, хвост шага (`stepContext`);
- сообщения человека на ветке;
- выводы инструментов, в том числе итоги фоновых задач;
- реплики живого сотрудника (`staff`, с 0.53 — `service.appendStaffMessage` и `flow.noteStaffReply`);
- тексты приложения из `knownTexts`.

**Не входят:** свои прошлые ответы агента и служебные сообщения приложения — вида `app` и «напиши первым»
(`conversation_started`). Нужны слова оттуда — назовите их в `knownTexts`.

**Реплика сотрудника.** Модели велено продолжать с учётом сказанного сотрудником. Повторит она ссылку или телефон из его
ответа — проверка не вырежет: текст реплики известен проверкам сам, `knownTexts` для него не нужен. Словами человека
реплика не становится: `person_link_view` берёт только реплики человека, ссылку сотрудника он не откроет. Ответ эксперта
кладите через `appendStaffMessage` или `noteStaffReply`, а не обычным сообщением собеседника: иначе он станет словами
человека и для `person_link_view`.

## Тексты приложения (`knownTexts`)

Первое сообщение, прощание, названия роликов, тексты нод — приложение вписало их само, они не стоят в инструкции целиком.
Без подсказки проверка вырежет ссылку из первого сообщения и сочтёт латинские слова оттуда чужими.

```ts
createChatServer({
  …,
  replyChecks: {
    checks: [foreignWords({ script: "cyrillic" }), unknownLinks({ appDomains: ["apps.example.com"] })],
    knownTexts: async ({ ownerId, chatId }) => [welcomeText, farewellText, ...(await videoTitles(chatId))],
  },
});
```

- Функция зовётся на каждую проверку: кэш — дело приложения.
- Сбой или не список — строка в `logError`, проверки идут без этих текстов.
- **Со сценарием** передайте `replyChecks` в `flow.withChat({ … })`: сценарий сам добавит к вашим текстам общую часть,
  ноды (название, инструкция, первое сообщение), `schedule.farewellText`, `dayFrame.hardText` и попутные задачи
  закреплённой за чатом версии. Чат без сценария получает только ваши.

```ts
const { service } = createChatServer(flow.withChat({ agent, replyChecks: { checks, knownTexts } }));
```

## Проверка текста вне хода

Приложение отправляет свой текст (например, итог своего инструмента, который склеивает с прощанием). Чтобы он прошёл те же
проверки, что и ответ агента:

```ts
const { text, notes } = await service.checkReply({ ownerId, chatId, text: finalAnswer });
```

- Те же проверки по очереди и тот же набор виденного: инструкция чата, блоки контекста, сообщения человека, выводы
  инструментов, `knownTexts`. Хвоста шага вне хода нет — его тексты назовите в `knownTexts`.
- `text` — текст после правок, `notes` — заметки проверок (то, что на ходе уходит строкой в журнал).
- Сбой проверки или пустой текст — как на ходе: остаётся текст до неё.
- Переписка — моделью чата, расход `answer_correction` без привязки к сообщению. Нет проверок — текст как есть.
- Необязательные поля: `messageId` (к какому ответу относится текст), `abortSignal`.
- Чужой или неизвестный чат — `ChatNotFoundError`.

## Расход и кэш

Переписка — отдельный запрос к модели. Его расход пишется с назначением `answer_correction` и входит в лимиты.
Инструкции переписки постоянные, меняется только текст после них: кэш провайдера работает и здесь. Проверки без
находок модель не зовут и ничего не стоят.
