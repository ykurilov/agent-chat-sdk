# Файлы приложения в поле ввода

Доступно с SDK 0.96.0. Все пакеты SDK обновляйте одной версией. Старые `attachmentsClient`,
`ingestFile`, `composerActions`, вставка файлов, перетаскивание файлов и стандартное меню сохраняются.

## Помощник поля

`useComposerHelper` экспортируется из `@ykurilov/agent-chat-react` и `/panel`.
Возвращает `ComposerHelper | null`. Работает в потомках `AgentChat`, а также в любых частях
`AgentPanelProvider`, включая свою оболочку панели над чатом. В закрытой панели, списке чатов,
без загруженного чата или без разрешённого плагина вложений возвращает `null`.

Помощник содержит `value`, `setValue`, `send`, `addFiles`, `addServerFiles`, `busy`, `blocked`, `canSend`.
`canSend` означает доступность отправки по состоянию чата; пустое поле и незавершённые загрузки
дополнительно проверяются обычным путём отправки. Для кнопок добавления проверяйте `canSend`.
Файловые команды хука отказывают при `canSend=false`. Сохранённая ссылка на помощника прежнего
чата/пользователя после переключения ничего не делает. Для нового действия берите помощника
текущего рендера; отложенные операции привязывайте к исходному чату.

`addServerFiles(drafts: ServerFileDraft[]): void` начинает добавление существующих серверных файлов:

```ts
interface ServerFileDraft {
  name: string;
  previewUrl?: string;
  ingest(signal: AbortSignal): Promise<ServerFileResult>;
}
```

`ServerFileResult` структурно совместим с `IngestFileResult` из
`@ykurilov/agent-chat-attachments`: `{ ok: true, attachment: { id, name, mediaType, kind, size,
textTokens?, textTruncated? } } | { ok: false, reason: string }`.

Приложение в `ingest` вызывает свой защищённый endpoint с `signal`, исходными chatId и ID файла.
Endpoint проверяет владельца и чат, вызывает серверный `attachments.ingestFile` и возвращает его результат.
Браузер не скачивает файл и не загружает его повторно. SDK не авторизует endpoint приложения.
`previewUrl` передаётся как есть; его доступом и сроком жизни управляет приложение, SDK не вызывает
для него `URL.revokeObjectURL`.

Плитка появляется сразу со статусом `uploading`; после успешного ingest готова к обычной отправке
через `attachment:<id>`. Обычные и серверные файлы делят лимиты и очередь из двух операций.
Размер, тип, суммарный текст и отказы показываются теми же сообщениями. На сервере остаётся
окончательная проверка файлов. Пользовательский `ingest` автоматически не повторяется.

Удаление плитки, уход или смена чата отменяют `signal`. Поздний результат не восстанавливает плитку;
для успешного позднего ingest SDK отправляет DELETE неприкреплённого файла по адресу исходного чата.
Это попытка очистки, без гарантии доставки; серверная политика хранения брошенных файлов сохраняется.
Ошибка отправки сообщения возвращает готовые файлы в поле. Пользовательские плагины вложений
могут реализовать необязательный `AttachmentsController.addServerFiles`; без него команда не действует.

## Меню «+» Одуванчика

В `AgentChat`/`AgentPanel` передайте `composerOptions.addMenu`:

```ts
addMenu?: {
  fromDevice?: { label: string } | false;
  items?: Array<{ id: string; label: string; icon?: ReactNode; onPick(): void }>;
}
```

Свой пункт открывает интерфейс приложения; оттуда используется `useComposerHelper`.
Свои пункты идут перед выбором файлов. Объект `fromDevice` заменяет стандартные «Файл» и
«Картинка» одной кнопкой с указанной подписью и прежним `accept`. `false` скрывает выбор файлов;
отсутствующее поле сохраняет оба старых пункта. Свои пункты доступны и без плагина вложений.
После выбора меню закрывается; занятый или заблокированный чат выключает меню.
Поддерживается в вариантах `standard` и `extended`; `compact` по-прежнему без меню вложений.
Другие скины могут поддержать это необязательное поле отдельно.

Перетаскивание без файлов не отменяется полем Одуванчика: обработчик родительской панели
получит собственный MIME-тип приложения. Настоящие файлы поле принимает как прежде;
родительская зона должна учитывать `event.defaultPrevented`, чтобы не добавлять их дважды.

## Уведомление сервера после записи сообщения

В `createAttachments` добавлен необязательный хук:

```ts
onFilesAttached?: (input: {
  userId: string;
  chatId: string;
  messageId: string;
  attachments: StoredAttachment[];
}) => void | Promise<void>;
```

Вызывается после успешной вставки нового сообщения человека с файлами, в том числе из пачки
мессенджера или поправки во время хода. Записи файлов принадлежат этому человеку и чату,
уже отмечены прикреплёнными, повторяющиеся ID убраны. Приём файла без отправки, отклонённое
сообщение, ошибка вставки, редактирование, импорт и повтор уже записанного сообщения хук не вызывают.
Обычный ответ и завершение хука не ждут друг друга. Синхронная ошибка и отказ Promise идут в
`logError(message, error)` сервиса и не меняют результат записанного сообщения.

Это уведомление один раз на успешную вставку, а не долговечная очередь: при остановке процесса
выполнение не гарантировано и автоматически не повторяется. Для библиотеки приложение само
делает операцию идемпотентной по `(chatId, messageId, attachment.id)` и организует восстановление,
если оно требуется. Чтение байтов и создание записей библиотеки остаются в приложении.
