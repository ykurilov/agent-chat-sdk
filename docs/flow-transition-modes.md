# Режимы переходов сценария

С 0.88.0 режим выбирается при запуске разговора. JSON графа не меняется.
`createAgentFlow({ transitionMode })` задаёт значение для новых чатов; поле `transitionMode`
в результате `loadFlow` или в `flow.adopt` переопределяет его для запуска. Тип -
`FlowTransitionMode`: `rails | advisor | free`. Без настройки действует `rails`.

Режим закрепляется в `FlowStore` при первом `pinChat` и сохраняется после перезапуска.
Смена настройки не переводит существующие чаты в другой режим. Для сравнения режимов
создавайте отдельные запуски с тем же графом и настройками судьи.

| Режим | Обычный `flow_exit` | Обычный судья после ответа |
|---|---|---|
| `rails` | положительное решение судьи разрешает переход, отрицательное запрещает | может подготовить переход сам, как прежде |
| `advisor` | положительный совет разрешает переход; отрицательный оставляет выбор модели | положительный результат становится советом модели на следующем ходе; сам разговор не переводит |
| `free` | проходит без судьи, если выход существует в текущем состоянии | не вызывается |

Во всех режимах стрелки текущего состояния, условия по данным, событиям и таймерам
проверяются кодом. `flow_exit` выбирает только обычные выходы словами и не может
форсировать остальные виды. Ограничения цепочки переходов, окончания разговора и
защищённых выходов сохраняются.

**Защищённые выходы `confirmation-judge` - исключение из таблицы.** Инструмент модели
их не исполняет даже с `confirm`. Существующая серверная проверка подтверждённой вехи
и актуальной реплики человека работает во всех трёх режимах и по-прежнему может
подготовить такой переход автоматически. `free` отключает обычного судью, но не защиту.

## Отрицательный совет и подтверждение

В `advisor` отрицательный ответ `flow_exit` содержит действительный результат судьи.
Модель может продолжить текущее состояние либо повторить тот же выход с `confirm: true`
и собственным `why`. Повтор проходит без второй проверки судьи и без блокировки
`claimAllowed`. Подтверждение действует только после отрицательного совета для того же
выхода, в том же ходе и том же посещении состояния. Прошлый ход, другое состояние или
`confirm` без совета обхода не дают. В `rails` это поле запрет судьи не отменяет.
Ошибка или отсутствие результата судьи не считаются отрицательным советом и не дают
права на обход.

Советы после ответа передаются в конце контекста `[flow:advice]`. Режим находится в
концовке `[flow:policy]`; неизменная часть инструкции и набор инструментов одинаковы
для режимов. Совет привязан к ветке и состоянию: запоздалый результат не переносится
в другой ход. После ответа судья работает в фоне, как и прежде. В eval вызывайте
`await flow.settled()` перед следующим сообщением, чтобы дождаться его результата.
Иначе следующий ход может начаться до готовности совета и безопасно пройти без него.

## Текстовый судья

По умолчанию остаётся Microsoft Decision через OpenRouter и существующий `judge.fallback`.
Для судьи с текстовым доводом задайте `judge.textModel: ModelChoice` из каталога приложения.
Это одна настройка для `rails` и `advisor`. `judge.fallback` остаётся обязательным полем
контракта; если задан `textModel`, обычная ветка Decision/fallback не используется.

Текстовая модель возвращает проверяемый JSON: для каждого выхода `exitId`, вероятность
`probability` от 0 до 1 и непустой `reason`. `confirmed` вычисляет SDK по общему
`judge.threshold` (по умолчанию 0.7). Ошибка, пропущенный/дублированный ID или неверный
формат приводят к отказу проверки, без молчаливой подмены другим судьёй. Вызов идёт
через `askModel` с `source: "judge"`, поэтому учитывает расходы и лимиты приложения.

Decision и старый fallback не выдают текстового довода. SDK не сочиняет его: совет
показывает реальную вероятность, порог и фразу «Текстового довода нет».
Для сравнения режимов оставляйте модель и порог судьи одинаковыми.

## События для eval

`onTransitionDecision(event: FlowTransitionDecision)` у `createAgentFlow` получает
результаты судьи и решения о переходах. Это основной канал аудита, в том числе для
фонового судьи. Во время инструмента копия также идёт в поток как `AppEvent`
`{ type: "flow.transition-decision", data: event }`; константа
`FLOW_TRANSITION_DECISION_EVENT` экспортируется из пакета. Итог оставшегося совета
также попадает в события `afterTurn`. Не рассчитывайте получить фоновые результаты
судьи из уже закрытого потока. При сборе нескольких каналов убирайте дубли по
`ownerId + chatId + id`.

Поля события:

| Поле | Содержание |
|---|---|
| `id`, `ownerId`, `chatId`, `turnId` | идентичность записи и хода |
| `flowId`, `versionId`, `mode`, `state`, `exitId` | запуск и проверяемый выход |
| `to` | выбранная цель, только у решения о переходе; отсутствие цели отличает отказ защищённого инструмента от серверного перехода |
| `phase` | `judge` или `decision` |
| `actor` | `judge`, `model` или `server` |
| `kind` | `claim` или `after_turn` |
| `judge` | `{ exitId, confirmed, probability, source, reason? }` либо `null`; `source`: `decision`, `fallback`, `text` |
| `decision` | значение из таблицы ниже |
| `adviceId` | ID исходного совета, если решение с ним связано |
| `modelWhy` | действительный аргумент `why` инструмента, если был; для молчаливого решения остаться довод не выдумывается |
| `at` | время записи в миллисекундах Unix |

| `decision` | Значение |
|---|---|
| `advice` | результат судьи; знак берётся из `judge.confirmed` |
| `unavailable` | судья не дал результата |
| `rejected` | `rails` запретил переход |
| `with_advice` | переход по положительному совету; `actor` отличает модель от автономного судьи |
| `against_advice` | модель явно подтвердила переход вопреки отрицательному совету |
| `without_judge` | обычный переход в `free`, `judge: null`; вероятность не выдумывается |
| `stayed` | полный ход закончился, неиспользованный совет остался в том же состоянии |
| `not_selected` | модель выбрала другой выход, а этот совет не использовала |
| `protected`, `blocked` | действие остановлено защитой/состоянием либо выполнено защищённым серверным путём (есть `to`) |

`stayed` описывает наблюдаемое поведение, а не доказательство внутреннего согласия модели.
Для прерванных, ошибочных и ожидающих разрешения ходов такой вывод не записывается.
Текст причины ограничен 2000 символами, `modelWhy` - 1000. Ошибка обработчика аудита
пишется в журнал и не отменяет переход. Это не транзакционная доставка журнала:
для надёжного eval сохраняйте callback самостоятельно и учитывайте повторные записи.
События решений дополняют прежний `onTransition`, который остаётся источником
фактически применённых переходов. Автономный судья сначала готовит pending-переход;
подготовленное решение не означает, что он уже применён.

## Хранилища и обновление

Обновите установленные пакеты SDK одной версией. SQLite и PostgreSQL применяют
миграцию flows `0004_transition_mode` автоматически. Старые строки получают `rails`.
Пользовательский `FlowStore` может сохранить прежний контракт для `rails`; для
`advisor/free` его `pinChat` должен сохранять и возвращать `transitionMode`, а
pending-записи - поддерживать `kind: "advice"`. SDK откажет при новом режиме, если
store не вернул поле. Формат графа, редактор и API приложения для eval не менялись.
