# Библиотека готовых картинок

Агент показывает человеку готовую картинку из каталога приложения: «покажи схему клетки» — в ответе картинка по его
ширине, под ней подпись. Нажал — окно просмотра на весь экран. Агент ничего не рисует: только выбирает из того, что
положило приложение. Это отдельный пакет `@ykurilov/agent-chat-image-library`.

Без пакета ничего не меняется.

## Включить

```bash
pnpm add @ykurilov/agent-chat-image-library
```

```ts
// сервер
import { createImageLibrary } from "@ykurilov/agent-chat-image-library";

const library = createImageLibrary({
  images: [
    {
      id: "cell",
      title: "Строение клетки", // видно под картинкой
      alt: "Схема клетки: ядро в центре, митохондрии и мембрана по краю", // обязательно: для незрячих и вместо картинки
      url: "/library/cell.png", // путь от корня своего сайта или https на домене из allowedHosts
      width: 1200, // размеры нужны, чтобы место под картинку было заранее, без прыжков ленты
      height: 800,
      description: "Из чего состоит живая клетка.", // по желанию, помогает поиску
      concepts: ["клетка", "органоиды"], // по желанию
      tags: ["биология"], // по желанию
    },
  ],
});

createChatHandler({
  …,
  agent: {
    instructions: appInstructions,
    tools: (model) => ({ ...appTools(model), ...library.tools(model) }),
  },
});
```

```tsx
// страница
import { imageLibraryClient } from "@ykurilov/agent-chat-image-library/react";
<AgentChat … images={imageLibraryClient} />; // так же у ChatWorkspace, AgentPanel и chatProps песочницы
```

## Каталог

Три способа, выбирайте по размеру и по тому, как часто он меняется.

- **Массив** — постоянный каталог. Проверяется сразу при `createImageLibrary`: пустой id, нет названия или `alt`, чужой
  адрес, размеры не целые, повтор id — исключение с id записи. Библиотека берёт себе замороженную копию: правка массива
  или записей потом ни на что не влияет. Новый каталог — новый `createImageLibrary` или функция.
- **Функция** `images: () => записи` (может быть `async`) — каталог меняется без перезапуска. Вызывается на каждом
  поиске и показе: новая картинка находится сразу, удалённую больше не показать. Негодная запись пропускается и один раз
  попадает в журнал (`logError`, по умолчанию `console.error`): только id и причина. При повторе id берётся первая.
- **`source: { search, get }`** — для большой базы или своего поиска. Обе функции получают `{ ownerId, chatId }`: можно
  учитывать права человека. Записи проверяются на каждом вызове.

Функция каталога, `search` и `get` должны ответить за 5 с. Не ответили, упали или вернули не список — `find_images` и `show_image` кончаются ошибкой `catalog_unavailable` с текстом
«каталог картинок сейчас недоступен» без подробностей, причина — в журнале. «Ничего не нашлось» — обычный результат с
пустым списком.

## Адрес картинки

Годится путь от корня своего сайта (`/library/cell.png`) или `https://` на домене из `allowedHosts`:

```ts
createImageLibrary({ images, allowedHosts: ["cdn.school.ru"] }); // сервер
createImageLibraryClient({ allowedHosts: ["cdn.school.ru"] }); // экран — те же домены
```

В `allowedHosts` — только имя хоста, без `https://` и порта: `"cdn.school.ru"`, а не `"cdn.school.ru:8443"`. Порт в самом
адресе картинки не проверяется: `https://cdn.school.ru:8443/a.png` годится. Пробелы в пути не годятся: пишите `%20`
(`/library/my%20cell.png`).

Не годятся `http://`, `//домен`, `data:`, `javascript:`, логин и пароль в адресе, хитрые пути вроде `/\домен`. Экран
проверяет адрес ещё раз: подделанная запись в базе не покажется, на её месте будет строка инструмента.

## Как агент находит картинку

Каталог в запрос модели не попадает. У агента два инструмента:

- `find_images({ query })` — ищет по названию, понятиям, тегам, описанию и `alt`, без регистра и с падежами. Отдаёт до 8
  подходящих: id, название, описание до 300 знаков, понятия и теги. Адреса модель не видит. Ничего не нашлось — пустой
  список и совет попробовать другие слова.
- `show_image({ id })` — показывает одну картинку. Сервер принимает только id из каталога: адрес или выдуманный id — отказ.
  Отказ — ошибка инструмента `ImageLibraryError` (`kind`: `not_in_catalog` или `catalog_unavailable`): в ленте строка
  «show_image: ошибка» с текстом, модель получает тот же текст и может поискать снова.
  После показа модель видит только «показано: название».

Описания и схемы инструментов одни и те же при любом каталоге: начало запроса к модели не меняется, и кэш модели цел.

## Вместе с генерацией картинок

`images` принимает и список клиентов. Созданные и готовые картинки живут в одном чате, окно просмотра листает все
картинки ответа подряд:

```tsx
import { imagesClient } from "@ykurilov/agent-chat-images/react";
import { imageLibraryClient } from "@ykurilov/agent-chat-image-library/react";

<AgentChat … images={[imagesClient, imageLibraryClient]} />;
```

Список можно создавать прямо в разметке: экран сравнивает его по содержимому и не перерисовывает ленту зря.

## Свой скин

Картинка библиотеки приходит в `GeneratedImages` (договор скина версии 26) с двумя необязательными полями:
`wide: true` — рисовать по ширине ответа со своей пропорцией, а не плиткой; `caption` у готовой картинки — подпись
под ней. Скин версии 25 работает без правок: картинка будет плиткой ближайшей обычной пропорции (1:1, 3:2, 2:3, 16:9, 9:16) без подписи. Края картинки другой пропорции он
может слегка обрезать. В Тандеме всё уже есть. Подробно — [skin-v26.md](./skin-v26.md).

## Если библиотеку выключили

Приложение убрало `library.tools(model)` из `agent.tools`, а в истории чата уже есть показы. Тогда ядро пересказывает
модели каждый такой вызов одной строкой «прошлый вызов, сейчас выключен» с входом и ответом JSON, вместе с адресом
картинки. Это общее поведение ядра для любого выключенного инструмента. После выключения эта строка от хода к ходу
одна и та же, так что кэш модели цел.

Картинка хранится в истории чата: видна после перезагрузки, в песочнице и в журнале.
