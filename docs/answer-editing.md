# Правка готового ответа в обычном чате

С 0.97.0 обычный HTTP-обработчик Next.js и Hono поддерживает правку текста ответа. По умолчанию адрес выключен. Приложение включает `answerEditing: true` в `createChatServer` / `createChatHandler` и разрешает `answerEditing` в `chatCapabilities`. Право проверяется на сервере на каждой записи; скрытая кнопка не заменяет проверку права.

На экране `AgentChat` со скином «Одуванчик» передайте `answerEditor={true}`. У законченного ответа появится кнопка «Изменить ответ» и штатное окно с текстом, «Сохранить» и «Отмена». Пустой и неизменённый текст не сохраняются. При отказе сервера черновик остаётся в окне. Ответы активного хода не правятся. После сохранения чат показывает новую ветку; право ручного переключения веток для этого не требуется.

Существующее `answerEditing={{ edits, renderEditor }}` сохраняет прежний контракт пользовательского редактора, в том числе в песочнице, и имеет приоритет перед `answerEditor`. Старый скин без необязательного `AnswerTextEditor` не показывает штатный редактор; собственный редактор работает как прежде. Изменение результатов инструментов остаётся возможностью API песочницы и серверного `service.editAnswer`, а не обычного HTTP-адреса.

## Поля приложения

Вместо `true` передайте объект `answerEditor` с `renderFields({ message, data, setData, disabled })`. Возвращённый React-элемент стоит под основным полем. `data` изначально `{}`; приложение задаёт свои ключи через `setData`. Так приложение размещает необязательное поле «Почему так лучше» без замены редактора целиком. Учитывайте `disabled`, пока правка отправляется. Для собственных меток доступен `answerEditor.edits`, карта прежнего типа `AnswerEditMark`.

SDK отправляет `data` вместе с правкой и передаёт её серверному хуку. Допускается JSON-объект до 16 КиБ в UTF-8, глубиной до 32. Не передавайте секреты: эти данные доступны коду приложения, который имеет доступ к серверному хранилищу. SDK не добавляет их в контекст модели и не выдаёт в браузерной истории. Поля приложения не меняют смысл правки: если сам текст не изменился, запись отклоняется как `nothing_changed`.

## Хук приложения и связь ответов

`onAnswerEdited(input)` вызывается после записи нового ответа и выбора его ветки. В `input`:

- `ownerId`, `chatId`;
- `sourceMessageId` - исходный ответ; `messageId` - новый ответ и ключ идемпотентности;
- `sourceText`, `text` - полный прежний и новый текст, текстовые части соединены пустой строкой;
- `editedAt`;
- `data`, если передана приложением.

Это отдельный хук: он вызывается и тогда, когда состояние сценария не изменилось. `onStateChanged` для журнала правок не подходит. Обработчик приложения должен переносить повтор с тем же `messageId` без дубликата. SDK повторяет отказавший хук до трёх раз в общем сроке 30 секунд, по очереди для каждого чата; `service.flush()` ждёт эту работу. Сбой хука пишется через `logError(message, error)` и не превращает уже записанную правку в HTTP-ошибку. Повторы живут в процессе и не являются долговечной очередью доставки после аварии сервера.

Связь с исходным ответом и данные приложения сохраняются долговечно в частях нового сообщения, без миграции схемы хранилища. Сервер читает запись через `answerEditOf(storedMessage.parts)` из `@ykurilov/agent-chat-core`; исходный текст остаётся в исходном сообщении. Это путь сверки журнала приложения после сбоя доставки. Проверку владельца и чата при доступе к raw storage выполняет приложение. Браузер получает только `message.metadata.answerEdit = { sourceMessageId, editedAt }`, без `data` и владельца. Данные записи удаляются из частей до передачи модели и клиенту. Общая шина `service.subscribeEvents` также получает `answer-edited` с владельцем, чатом и двумя id, без текстов и полей приложения. Открытая вкладка обновляет историю по этому событию.

SDK не удаляет старый ответ, не меняет исходную ветку и не реализует «Убрать правку». Приложение использует свои `messageActions`, `answerEditing.edits` и `selectBranch` как прежде.

## HTTP

`POST {basePath}/:chatId/messages/:messageId/answer-edit`, JSON `{ text, data? }` → `{ messageId }`. Обычные проверки входа, владельца, origin и права `answerEditing` сохранены. Текст до 100 000 знаков, тело запроса до стандартного 1 МиБ. Поле `toolOutputs` здесь запрещено.

Непринятая правка: `{ error: { kind: "answer_edit", reason } }`. Причины отсутствующего чата/ответа дают 404, занятости или другой ветки - 409, неверного текста/данных - 400. Запрещённое право - обычный 403 `action_forbidden`. Выключенный адрес - 404. Отмена окна не делает запроса. Ответ от прежнего чата или ветки не переключает текущую ленту.

## Как обновить приложение

Обновите установленные пакеты SDK одной версией. Включите серверный `answerEditing: true`, право `chatCapabilities.answerEditing` и клиентский `answerEditor`. Для дополнительных полей задайте `renderFields`; для своего журнала подключите `onAnswerEdited`. Базу данных SDK менять не требуется. Собственный редактор песочницы переносить не требуется.

Если приложение исчерпывающе разбирает типы SDK, учтите новый `ChatEvent` с `type: "answer-edited"` и причину `AnswerEditErrorKind: "invalid_data"`. Для своего скина - [договор 32](skin-v32.md).
