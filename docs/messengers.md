# Мессенджеры

Чат приложения в Telegram, VK и MAX. Человек подключает свой аккаунт один раз, дальше пишет боту, а отвечает тот же
агент, что и в вебе: с теми же инструментами, памятью и лимитами. Фоновые задачи, подтверждения и «Задача готова»
тоже приходят в мессенджер, а с кнопки «Открыть в приложении» можно вернуться на сайт.

Это отдельный пакет `@ykurilov/agent-chat-messengers`. Без него ничего не меняется.

## Включить

```bash
pnpm add @ykurilov/agent-chat-messengers
```

```ts
import { createMessengers } from "@ykurilov/agent-chat-messengers";
import { createSqliteMessengerStore } from "@ykurilov/agent-chat-messengers/sqlite";
import { telegramBot } from "@ykurilov/agent-chat-messengers/telegram";

const messengers = createMessengers({
  store: await createSqliteMessengerStore({ filePath: "./data/chat.db" }),
  bots: [telegramBot({ token, username: "my_school_bot", receive: { polling: true } })],
  service,                              // служба чата, которую вернул createChatServer; без неё — бот только для привязки
  resolveUser: async (request) => currentUser(request),
  basePath: "/api/messengers",
});
app.all("/api/messengers/*", (c) => messengers.handler.fetch(c.req.raw));
await messengers.start();
```

Панель «Подключить мессенджер» работает с чужой страницы (фронт на другом адресе, GetCourse), только если эта страница
вписана в `allowedOrigins` у `createMessengers`, как у чата. Иначе выдача и снятие привязки получают 403 `forbidden_origin`.

Что нужно знать про боты (вебхук или опрос, прокси для России, режим приватности в группах Telegram), все настройки
со значениями по умолчанию, голосовые ответы, группы и хранилища — в [README пакета](../packages/messengers/README.md).

## Как это выглядит для человека

1. На странице приложения — панель «Подключить мессенджер». Нажал «Подключить» — получил ссылку с кодом на 15 минут.
2. Открыл ссылку в мессенджере, нажал «Начать» — аккаунт привязан.
3. Пишет боту обычными сообщениями, присылает файлы и голосовые (если приложение их подключило).
4. Ответ печатается по ходу. `/stop` — остановить.
5. Задача ушла в фон — приходит карточка с кнопкой «Отменить задачу», потом «Задача готова». Нужно разрешение —
   карточка «Разрешить / Отклонить».

Режим `conversations: "many"` добавляет `/new` и `/chats`. Чаты, созданные из мессенджера, в списке чатов
приложения помечены значком мессенджера.

## Сигнал о привязке

Приложение может узнать, что человек привязал аккаунт: в `createMessengers` есть `onLinked(link)`. Её вызывают после
того, как привязка сохранена, и ждут до ответа человеку. Неверный, просроченный и уже использованный код сигнала не
дают. Ошибка в `onLinked` попадает в `logError`, а человек всё равно получает «привязано».

```ts
createMessengers({
  // …
  onLinked: async ({ userId, messenger, externalUserId }) => {
    await grantLimitReset(userId, `${messenger}:${externalUserId}`);
  },
});
```

Сигнал может прийти повторно для того же аккаунта мессенджера: человек отвязал и привязал снова. Награду выдавайте
идемпотентно, например по паре `messenger` + `externalUserId`. Аккаунт, уже привязанный к другому пользователю, чужой код
не переносит: человек получает фразу `linkTaken`, привязка прежняя.

Об отвязке приложение узнаёт через `onUnlinked(link)`: человек отвязал аккаунт в приложении. Сигнал приходит, когда привязки в базе уже нет; его сбой отвязку не отменяет. Он может
повториться, поэтому обработчик должен быть идемпотентным — например, «убрать из рассылки, если есть». Ответ на отвязку (204) ждёт, пока обработчик закончит,
поэтому долгую работу лучше ставить в очередь. Подробно и
рецепт бота только для привязки (без `service`, без меню) — в [README пакета](../packages/messengers/README.md).

## Свои фразы бота

Любую фразу бота можно заменить: `texts` в `createMessengers` — для всех ботов, `texts` у бота — только для него.
Пустая фраза — бот ничего не отправляет, но нажатие своей кнопки всё равно подтверждает, а пустой итог убирает
строку «Работаю…». Фразы над кнопками заглушить нельзя. Так делается бот только для привязки и уведомлений: молчащий ВК-бот или
Telegram-бот с одной фразой. Список фраз, порядок перекрытия и рецепт с кодом — в README пакета, раздел «Свои фразы
бота».

## Несколько сообщений подряд

Человек пишет «привет», «у меня вопрос», «вот ссылка» — бот ждёт, пока он замолчит на 3 секунды, и отвечает одним
ответом на всё. Пишет, пока бот ещё отвечает, — после ответа бот отвечает одним ответом на всё накопленное. Такие
сообщения попадают в историю и в веб-вкладку только после ответа. В истории чата сообщения остаются отдельными.

```ts
createMessengers({ /* … */ messageBursts: { quietMs: 5000 } }); // своё окно тишины
createMessengers({ /* … */ messageBursts: false });             // как до 0.54: ответ на каждое сообщение
```

Работает в личных чатах. Группы и нажатия кнопок не склеиваются. Цена — ответ начинается на окно тишины позже.
`/stop`, пока бот ждёт тишины, отменяет ответ: бот пишет «Остановил.», сообщения остаются в истории, следующее
сообщение получит ответ на всё сразу. Открытая веб-вкладка того же чата видит сообщения сразу, ещё до ответа.
Устройство и вызов для своего канала — [getting-started](./getting-started.md), раздел «Несколько сообщений подряд».

## Надёжность

Итоги и карточки сначала записываются в базу, потом отправляются. Сервер упал — после старта недоставленное уходит
снова. Доставка «хотя бы раз»: возможен повтор того же сообщения, потерь нет. Повторный вебхук мессенджера
распознаётся и не запускает агента второй раз.

Входящее сообщение тоже не теряется. Сервер упал посреди обработки — сообщение подбирает живая копия через 2 минуты
или эта же после перезапуска. База не приняла сообщение — мессенджер получает ошибку и присылает его снова. Повтор
сверяется с историей чата, поэтому агент не отвечает на одно сообщение дважды. Подробности — в README пакета, раздел
«Приём сообщений».

```tsx
import { MessengerConnect } from "@ykurilov/agent-chat-messengers/react";
<MessengerConnect url="/api/messengers" skin={myMessengersSkin} />;
```

`MessengersSkin` v1.
