# История браузера по запросу

С 0.89.0 `AgentChat`, `ChatWorkspace` и `useAgentChat` принимают `history: "compact"`.
По умолчанию остаётся `"full"`. Сервер обновляется вместе с React-пакетом; миграций базы нет.

Начальный HTTP-ответ содержит последние 30 публичных сообщений. Текст ответов, заголовки
размышлений, типы, позиции и состояния частей сохраняются. Завершённые reasoning и обычные
tool input/output заменяются ссылками `message.metadata.historyDetails[index]` с `type` и `revision`.
Раскрытие строки загружает оригинальную публичную часть. Длинные подробности имеют собственную прокрутку и занимают не больше 60% видимой высоты. В простом виде раскрываются группа шагов,
затем отдельный шаг. Скриншоты внутри outputs приходят с подробностями.

Идущий ответ, ожидающее подтверждение, основные и зарегистрированные custom widgets, `helper_*`,
пользовательские сообщения и прямые file-части остаются полными. Это сохраняет approval/restore и
интерактивные состояния. Поэтому общего жёсткого лимита размера страницы нет. Большие тексты,
вложения, app state и метаданные также могут увеличить ответ. Сервер пока читает полную публичную
ветку и только затем проецирует её для браузера: это сокращение HTTP payload, не SQL-пагинация.
Живой SSE и возобновление потока сохраняют прежний протокол.

## Контракт приложения

`onFeedChange` получает прежние `messages`, `busy` и дополнительное `change`:

- `kind: "live"` - изменение живой ленты;
- `"history"` - первоначальная загрузка или перечитывание;
- `"branch"` - явный выбор ветки;
- `"older-page"` - добавление старой страницы;
- `"details"` - догрузка части либо полного сообщения для редактора.

`change.historyComplete` означает, что загружены все публичные сообщения ветки, а не все детали.
`change.view` в compact-режиме содержит `mode`, opaque `branch`, `olderCursor`, `headMessageId`,
`totals: { messages, assistantAnswers }` и `stateBefore`.

`headMessageId` - последний ID **полной публичной** capability-filtered истории до нарезки,
совпадающий с `service.peekHistory(...).messages.at(-1)?.id` при том же состоянии. Это не raw head
служебных записей. Totals - снимок всей публичной ветки на этот head; это не продуктовые счётчики.
После живого хода снимок обновляется отдельно; приложение не должно считать каждое уведомление
`onFeedChange` новым ответом. `stateBefore` сохраняет состояние до начала загруженного окна для
`useChatState`. Поля самого приложения, основанные на содержимом скрытых outputs, требуют
отдельного компактного server endpoint либо собственного live event.

Для своей ленты `useAgentChat` отдаёт `loadOlder()`, `loadingOlder`, `olderFailed`,
`loadHistoryDetails("messageId:partIndex")`, `historyDetailStates` и `loadHistoryMessage(messageId)`.
Последний метод получает полное публичное сообщение перед редактированием. Возвращаемый boolean
означает принятую догрузку; false также возвращается при отменённом/устаревшем запросе.
Штатный редактор ответа делает это автоматически. Свои actions/editors не должны сохранять
облегчённые parts как полную историю. Ссылки `historyDetails` показывают, какие части ещё неполны.

Штатная лента подгружает старые сообщения при прокрутке вверх и сохраняет якорь. Есть также кнопка
ручной загрузки. Ошибка details/page локальна и допускает повтор, не переводит чат в «Нет связи».
Опциональный `labels.history` задаёт `older`, `loading`, `failed`; старые словари получают значения
по умолчанию. Поздние ответы после смены чата/ветки/перечитывания отбрасываются, включая JSON decode.

## HTTP

Прежний `GET /:chatId` остаётся полным. Opt-in:

- `GET /:chatId?history=compact` - последняя страница;
- `?history=compact&before=<olderCursor>&branch=<branch>` - предыдущая страница;
- необязательный `limit` 1..100; `through=<oldest-loaded-id>` удерживает загруженное окно при reload;
- `GET /:chatId/history-part?branch=...&messageId=...&partIndex=...&revision=...`;
- `GET /:chatId/history-message?branch=...&messageId=...&revision=...` - revision из `metadata.historyRevision`;
- `POST /:chatId/branch?history=compact` возвращает облегчённую историю выбранной ветки.

В каждой выдаче сначала проверяются владелец, права приложения и текущие capabilities. Details
ищутся только в текущей публичной ветке и сверяются по revision. Нет доступа - прежние 401/404;
изменение ветки/части - 409 `history_changed`; неверные параметры - 400. Ответы private/no-store.
`branch` и revision - непрозрачные значения, не права доступа и не raw storage ID.

## Что остаётся полным

`service.getHistory`, `service.peekHistory`, `storage.getMessage`, модельный контекст и
`replayPastTurns` не меняются. Серверная бизнес-логика, восстановление parent chain и gates используют
прежние raw/full handles. Compact DTO не сохраняется в БД и не подменяет сообщения для модели.
Не включайте браузерный opt-in, пока обработчики `onFeedChange`, подсчёты по всем ответам и чтение
полных outputs не переведены на обозначенную границу.
