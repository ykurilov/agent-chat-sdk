# Запись действий и потеря аренды хода

Обычный ход не продолжается автоматически после падения сервера. Сохранённая часть ответа остаётся в истории; брошенный `streaming` становится `interrupted`. Подтверждение `awaiting_approval` сохраняется и ждёт человека.

## До выполнения инструмента

Ядро ждёт успешную запись полного намерения вызова: имя, id и готовый ввод. Промежуточный `input-streaming` не разрешает действие. Отказ записи или отсутствие подтверждения за 5 секунд даёт ошибку инструмента без выполнения `execute`. Поздний успех той же записи не запускает уже отклонённый вызов. Правило действует и для асинхронных генераторов. Перед выполнением повторно проверяются закрытие шага и сигнал остановки.

Это не журнал внешних действий. Если письмо, платёж или чужой API успели принять действие, а ответ потерялся, SDK не знает его исход. Инструменту приложения по-прежнему требуется свой ключ идемпотентности. Автоматического повтора такого действия после перезапуска нет.

## Потеря аренды

У каждого захвата чата свой токен, включая повторный захват той же копией. Отказ или ошибка продления прерывает ход. Если продление зависло, локальный сторож останавливает ход по последнему подтверждённому сроку. Запоздалое продление не возвращает потерянное поколение. При выходе ожидание renewal ограничено последним подтверждённым сроком; поздний результат очищается своим токеном и не удаляет аренду нового поколения. Новые вызовы инструментов не начинаются; уже начатому действию передаётся сигнал остановки, но SDK не может отменить принятый внешний эффект.

Проверка ввода приложения не занимает аренду: другая копия может успеть принять ответ, пока проверка ждёт. Перед записью перечитывается актуальное ожидание, а перед запуском проверяется видимость ответа в ветке. Частичное решение по нескольким ожидающим подтверждениям или виджетам может записаться без запуска хода. Последний ввод, который возобновляет инструмент или модель, требует собственного поколения аренды; пока её держит другая копия, возвращается существующий `ChatBusyError`, а этот ввод остаётся для повтора.

Записи ответа проверяют токен в самой операции хранилища. Старый ход не перезаписывает ответ нового держателя: это касается вставки ответа, промежуточных и конечных записей, продолжения подтверждения и знака жизни. Успешная конечная запись остаётся действительной, если аренда потеряна после её commit. При зависшей промежуточной записи потерявший аренду ход освобождает завершение, а поздняя запись всё равно проходит ограду хранилища.

## Восстановление при запуске

Для хранилища с `listSilentAnswerIds` безопасный периодический обход запускается при создании службы. Ответ без знака жизни 15 секунд помечается прерванным на ближайшем обходе (раз в 5 секунд). Живые ответы этой копии и `awaiting_approval` не прерываются. Обход не запускает модель и не повторяет инструменты. `flush` останавливает обход; службу и хранилище завершайте в обычном порядке.

Явный `await chat.recoverInterruptedAnswers()` при старте сохраняйте: он сразу выполняет проверку и восстанавливает существующие дополнительные механизмы SDK. `{ soleServer: true }` разрешён только для действительно единственной копии: он снимает чужие аренды прошлого запуска. Автоматический обход не делает этого предположения и сам не возобновляет брошенные пачки сообщений или фоновые задачи. На хранилище без знаков жизни ядро пишет предупреждение; для единственной копии обязателен прежний явный startup-вызов.

## Как обновить приложение

Все установленные пакеты SDK обновляются одной версией. Встроенные memory, SQLite и PostgreSQL готовы; новых таблиц и миграций нет. Приложения со встроенными хранилищами не меняют обработчики инструментов или startup-вызовы.

Обёртки встроенного хранилища тоже передают guard-параметры без потерь и исполняют тот же договор.

Собственный адаптер, поддерживающий `claimChatTurn` и `releaseChatTurn`, должен объявить `guardedTurnWrites: true` и реализовать `ChatTurnWriteGuard.expectedTurnHolder` атомарно в `insertMessage`, `updateStreamingMessage`, `finishMessage`, `updateAwaitingMessage` и `markAnswerAlive` (если последний есть). Совпадение держателя и неистёкший срок проверяются вместе с записью. При отказе — `ChatTurnLeaseLostError`; без guard действуют прежние правила. Guard не сохраняется в сообщении. Объявлять capability без выполнения условий нельзя. Ядро отказывает при создании службы с арендой, но без capability.

Прогоните экспортируемый `describeChatStorageContract`, включая `chatTurnLease: "required"`, на своём адаптере. Адаптер без распределённой аренды сохраняет прежний договор одной копии сервера; этот выпуск не добавляет ему распределённой защиты.

Проверьте обычный ответ, успешный инструмент и подтверждение после перезапуска. При сбое записи намерения внешний эффект должен отсутствовать, а после потери аренды старый держатель не должен завершать ответ новой копии. Точное восстановление неизвестного внешнего эффекта этот выпуск не обещает.
