# Договор скина 31: шапка и итог приложения

К [версии 30](skin-v30.md) добавлены необязательные `ChatSkin.Layout.header?: ChatHeaderView` и `completion?: ReactNode`. Остальные части договора неизменны.

`ChatHeaderView` — нейтральные `{ title: string; aside?: ReactNode; headingLevel?: 1 | 2 | 3 }`. Скин оформляет заголовок своей системой. В Одуванчике это DS ChatHeader: внутри уже есть `yk-chat-column`, вторую колонку вокруг внутреннего содержимого не добавляют. Значение `scrolled` скин вычисляет по своему единственному `scrollRef`, тень появляется при scrollTop > 0.

`AgentChat` передаёт `completion` после загрузки истории, если нет ошибки загрузки и SDK не ведёт ответ (`busy` равен `false`). Значение null/undefined/false означает отсутствие итога. Скин помещает узел после ленты в том же скроллере и скрывает оболочку поля атрибутом hidden. Сам Composer остаётся смонтированным, черновик и контроллеры не сбрасываются. Это оформление приложения, а не статус сервера: никакого закрытия чата, автоматического текста или инструментального результата не возникает.

Снятие узла возвращает Composer. Скин не переносит фокус сам. Явное действие приложения может после обновления вернуть фокус в поле. Автоматическое появление/снятие итога не должно перехватывать фокус читателя. Пока идёт ответ, диктовка, обработка диктовки или голосовой диалог, итог отложен: управление остановкой остаётся доступным. SDK сам не останавливает голосовой ввод ради карточки.

Без новых свойств поведение прежнее. Дополнительные необязательные поля структурно совместимы с существующими скинами; чтобы показывать новые части, пользовательский Layout должен их обработать. Оба официальных скина поддерживают слоты; DS импортируется только скином Одуванчика, пакет React не зависит от DS.

Приложение определяет заголовки, подписи прогресса, пункты done/later и все действия. Скин не распознаёт бизнес-итог по тексту модели или DOM. DS CompletionCard можно передать как ReactNode, данные карточки в договор React не копируются.
