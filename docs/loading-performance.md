# Загрузка чата и лёгкие входы

## История и подписка

Обновите сервер и React-пакет одной версией. Дополнительных настроек не требуется.
`GET /:chatId` возвращает `x-agent-chat-history-version`, отпечаток полного авторизованного снимка до compact-пагинации. Клиент запоминает версию только применённого снимка и передаёт её в `GET /:chatId/watch?historyVersion=…`. Сервер сначала подписывается на события, затем сверяет снимок и возвращает `x-agent-chat-history-match: 1` только при совпадении. В этом случае повторный HTTP GET истории не выполняется. Изменение между запросами, переподключение к другой копии сервера и неизвестный/отсутствующий заголовок не скрывают обновлений: при несовпадении работает прежнее перечитывание, события во время сверки стоят в открытом потоке.

Сверка пока читает историю на сервере. Оптимизация убирает повторный сетевой запрос и передачу тела, а не второе чтение базы. Сырые серверные история/контекст и compact paging/details не меняются. Если приложение предоставляет CORS, для этой оптимизации браузеру должны быть доступны оба названных response header; без них остаётся прежнее безопасное поведение.

Меню моделей в SDK уже запрашивается один раз за жизнь хука для одного API. Дополнительный запрос из формы настроек приложения SDK не объединяет: приложение управляет им самостоятельно. Глобального кэша каталога и новых правил его актуальности этот выпуск не вводит.

## Сохранённый текст без интерфейса чата

```tsx
import { OduvanchikAgentText } from '@ykurilov/agent-chat-skin-oduvanchik/text';
import '@ykurilov/agent-chat-skin-oduvanchik/text/styles.css';

<OduvanchikAgentText markdown={text} />
```

Вход работает без ChatLabelsProvider, хуков и DOM, подходит для React Server Components. Стили ограничены `.oduvanchik-message-text`, без preflight и глобального сброса. Если страница уже использует основной CSS скина, дополнительный CSS не обязателен. Markdown/GFM, внешние ссылки, таблицы и защита от внешних изображений сохранены. Это **статический текст**: у кода нет интерактивной кнопки копирования, Mermaid и HTML-demo показываются кодом. Для интерактивного ответа сохраните прежний импорт из корня пакета.

Необязательные подписи передаются через `labels`. Экспортированы `OduvanchikTextLabels`, `russianOduvanchikTextLabels` и `englishOduvanchikTextLabels`; провайдеры чата и Тандема этот вход не читает. `streaming` принимается для совместимости вызова, но сам по себе не запускает поток.

## Наличие сообщений и индекс расходов

```ts
import { hasChatMessages } from '@ykurilov/agent-chat-core';
const populated = await hasChatMessages(storage, chatId);
```

У встроенных PostgreSQL/SQLite это один `SELECT 1 … WHERE chat_id = … LIMIT 1`, без parts, сортировки и чтения всех связей. В памяти проверяются записи. Считаются любые сообщения чата, включая служебные и другие ветки, как у прежнего `listMessageLinks(chatId).length > 0`. Метод **не проверяет владельца**: авторизацию приложение выполняет до него. Отсутствующий/пустой чат даёт `false`.

`ChatStorage.hasMessages` необязателен для обратной совместимости пользовательских хранилищ. `hasChatMessages` использует его при наличии, иначе прежний `listMessageLinks`. Для своего хранилища добавьте метод, если важна стоимость запроса.

Миграция PostgreSQL `0018_usage_created_index` добавляет `agent_chat.usage_records_created_idx` по `created_at`. Применяется штатным запуском хранилища, старые составные индексы сохранены. Поведение учёта расходов не меняется.
