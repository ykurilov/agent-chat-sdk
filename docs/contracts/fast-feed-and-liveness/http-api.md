# Contract: HTTP-адреса — дополнения 002

Дополняет [договор 001](../basic-agent-dialog/http-api.md): адреса, коды
ответов и тела те же. Меняются только ответы-потоки и появляется одна настройка.

## Настройка обработчика

```ts
createChatHandler({
  …как в 001,
  /** Промежуток между признаками жизни в потоках ответа. По умолчанию 10 000 мс. */
  heartbeatIntervalMs?: number,
})
```

Значение меньше 1000 мс — ошибка при создании обработчика (слишком частые пинги — пустая
нагрузка на сеть телефона).

## Признак жизни в потоках

Касается `POST …/messages`, `POST …/retry` и `GET …/stream` с ответом `200`.

- Заголовки: `UI_MESSAGE_STREAM_HEADERS` SDK, как в 001, плюс
  `x-agent-chat-heartbeat-ms: <heartbeatIntervalMs>`.
- Сразу после заголовков сервер шлёт SSE-комментарий `: ping\n\n`, затем повторяет его
  каждые `heartbeatIntervalMs`, пока поток открыт. Комментарий стоит только между целыми
  событиями `data: …\n\n`, никогда внутри.
- Клиент SDK комментарии пропускает (research R7): они не попадают в сообщение, реестр
  идущих ответов и хранилище (FR-010).
- Поток закрыт (ход окончен или клиент отключился) — таймер остановлен, пингов нет.
- Серверный срок первого куска ответа (60 с) пингов не видит и работает как в 001 (FR-015).

Пример начала потока:

```text
: ping

data: {"type":"start","messageId":"…","messageMetadata":{…}}

data: {"type":"start-step"}

: ping

data: {"type":"reasoning-start","id":"…"}
```

## Что не меняется

- `GET …/stream` отдаёт идущий ход с начала; `204`, если хода нет.
- Отключение вкладки только отписывает слушателя; ход на сервере идёт дальше и не
  перезапускается при подключении (FR-015).
- `POST …/stop` из любой вкладки останавливает ход.
- Ответы без потока (`GET` истории, `POST` создания, `POST …/stop`, ошибки) пингов не несут.
