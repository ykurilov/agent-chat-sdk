# Data Model: Быстрая лента, живая связь и пакет Тандема

Хранилище, формат сообщений и `formatVersion` **не меняются**: всё новое живёт в памяти
вкладки или в потоке ответа и нигде не сохраняется. Модель данных 001 действует без правок.

## Окно ленты (вкладка, `message-feed.tsx`)

| Поле | Тип | Смысл |
|---|---|---|
| `messages` | `AgentChatMessage[]` | вся история в памяти вкладки (как в 001) |
| видимый диапазон | индексы `[start, end]` | считает библиотека окна; плюс запас 200 px сверху и снизу |
| `keepMounted` | `number[]` | индекс растущего ответа, пока идёт ответ; иначе пусто |
| `stuckToBottom` | `boolean` | расстояние до низа < 96 px; при открытии и после отправки — `true` |
| `startMargin` | `number` px | расстояние от верха скроллера скина до начала ленты; мерится |

Правила:
- Число смонтированных сообщений ограничено высотой экрана и запасом, не длиной чата
  (FR-001, SC-003: ≤ 40).
- Прокрутка собеседником вверх снимает `stuckToBottom`; прокрутка к низу, отправка и
  открытие чата — ставят.
- Рост содержимого при `stuckToBottom` ведёт скроллер вниз (FR-004).

## Раскрытые части (вкладка, `expanded-parts.ts`)

| Поле | Тип | Смысл |
|---|---|---|
| ключ части | `` `${messageId}:${partIndex}` `` | стабилен: части ответа только дописываются |
| множество раскрытых | `Set<string>` | нет ключа — часть свёрнута (по умолчанию всё свёрнуто, как в 001) |

- Живёт в `AgentChat`, сбрасывается при смене `chatId`.
- Подписка по ключу (`useSyncExternalStore`): переключение одной части перерисовывает только её.

## Признак жизни (поток ответа, `heartbeat.ts`)

| Поле | Тип | Смысл |
|---|---|---|
| комментарий | `": ping\n\n"` | SSE-комментарий, не событие; SDK его пропускает |
| `heartbeatIntervalMs` | `number`, ≥ 1000, по умолчанию 10 000 | настройка `createChatHandler` |
| заголовок | `x-agent-chat-heartbeat-ms` | сообщает интервал вкладке |

Не проходит через реестр идущих ответов и хранилище; не повторяется при подключении к ходу.

## Состояние связи (вкладка, `use-agent-chat.ts` + `liveness/`)

| Поле | Тип | Смысл |
|---|---|---|
| `connection` | `"online" \| "reconnecting" \| "offline"` | см. [contracts/liveness.md](./liveness.md) |
| `lastByteAt` | `number` (мс, `performance.now()`) | время последнего байта потока ответа, включая пинги |
| `silenceLimitMs` | `number` | `max(silenceTimeoutMs, 3 × heartbeat из заголовка)` |
| номер попытки | `0..3` | текущая попытка серии |
| отмена серии | `AbortController` | «стоп» и размонтирование прерывают попытки |

Переходы — таблица в [contracts/liveness.md](./liveness.md). Инварианты:
- в `reconnecting` недописанный ответ остаётся на экране без отметки «прерван»;
- отметка `interrupted` ставится во вкладке только при переходе в `offline`; на сервере ход
  не трогается (FR-015);
- после успешной попытки лента — это история сервера плюс ход, повторённый с начала:
  ответ совпадает с сохранённым на сервере (SC-005).

## Настройки живости (вкладка)

| Поле | По умолчанию | Ограничение |
|---|---|---|
| `silenceTimeoutMs` | 30 000 | действует не меньше `3 × heartbeat` |
| `reconnectDelaysMs` | `[0, 2000, 5000]` | число элементов = число попыток |
| `requestTimeoutMs` | 10 000 | срок попытки целиком и запросов без потока |
