# Contract: живая связь во вкладке

Пакет `@ykurilov/agent-chat-react` 0.2.0. Серверная сторона — [http-api.md](./http-api.md).

## Настройки

```ts
interface LivenessOptions {
  /** Сколько тишины терпеть в потоке ответа. По умолчанию 30 000 мс. */
  silenceTimeoutMs?: number
  /** Паузы перед попытками переподключения. По умолчанию [0, 2000, 5000]. */
  reconnectDelaysMs?: readonly number[]
  /** Срок одной попытки и любого запроса без потока. По умолчанию 10 000 мс. */
  requestTimeoutMs?: number
}

useAgentChat({ api, chatId, fetch?, liveness?: LivenessOptions })
<AgentChat api chatId skin liveness? />
```

Действующий срок тишины — `max(silenceTimeoutMs, 3 × x-agent-chat-heartbeat-ms)`: вкладка
никогда не ждёт меньше трёх признаков жизни сервера (FR-017), даже если приложение задало
меньше.

## Состояние

```ts
/** Как вкладка видит связь с сервером. Экспортируется из пакета. */
type ConnectionState = "online" | "reconnecting" | "offline"

interface AgentChatState {
  …как в 001,
  connection: ConnectionState
}
```

| Состояние | Когда | `busy` | Что видит собеседник |
|---|---|---|---|
| `online` | обычная работа | как в 001 | как в 001 |
| `reconnecting` | тишина дольше срока, обрыв потока по сети, срок отправки истёк; пока идут попытки | `true` | «Переподключаемся…», недописанный ответ на месте, «стоп» доступен |
| `offline` | попытки исчерпаны; история не загрузилась по сети или сроку | `false` | «Нет связи с сервером» и «Повторить»; последний ответ помечен «Ответ прерван» |

Переходы:
- `online → reconnecting`: сторож тишины, сетевой обрыв потока, срок отправки.
- `reconnecting → online`: попытка удалась (подключились к ходу или показали готовый ответ).
- `reconnecting → offline`: три попытки не удались.
- `offline → reconnecting`: «Повторить», событие `online`, вкладка снова видна.
- `reconnecting → online` через «стоп»: попытки отменены, ответ помечен остановленным,
  `POST …/stop` ушёл на сервер (как в 001).

`retry()` в состоянии `offline` запускает новую серию попыток: перечитывает историю и
подключается к идущему ответу, если он есть (FR-013a). Сообщение, которое не дошло до сервера
(по истории его нет), отправляется заново, как в 001.

## Ошибки транспорта

Обёртка `fetch` транспорта заменяет сетевые `TypeError` и истечение сроков своими
`ConnectionLostError` и `ConnectionSilentError` (research R9). Отмена пользователем
остаётся `AbortError`. Приложение эти ошибки не видит: они внутренние.
