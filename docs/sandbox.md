# Песочница агента

Страница для админа приложения, где можно разговаривать с боевым агентом и видеть, что он делает под капотом: каждое
обращение к модели (что ушло, что пришло, сколько токенов и денег) и каждый вызов инструмента. Любое сообщение можно
поправить, правка создаёт новую ветку. Модель и системную инструкцию можно сменить для одного чата, боевая при этом не
меняется. Это отдельный пакет `@ykurilov/agent-chat-sandbox`.

Без пакета ничего не меняется: ни кода, ни таблиц, ни записи журнала, запрос к модели в боевом чате остаётся тем же.

## Что видит админ

- Список своих песочных чатов: создать, переименовать, удалить. Чужие песочные чаты не видны.
- Рядом с чатом журнал: обращения к модели (инструкция, сообщения, инструменты, настройки, ответ, токены, кэш, цена,
  время) и вызовы инструментов (вход, выход, ошибка, длительность). Повторы после сбоя, сжатие истории и запись памяти
  тоже видны, с пометкой назначения.
- Правка любого сообщения. Вопрос человека правится как в обычном чате. В ответе агента правятся текст и результаты
  обычных инструментов (любой JSON до 64 КБ); вызовы, картинки, видео и ответы на виджеты остаются как были, рассуждения
  модели убираются. Такой ответ помечен «Изменено человеком», а вызов с новым результатом — «Результат изменён».
- В шапке чата: выбор модели и редактор системной инструкции. Правка инструкции действует только в этом чате; служебные
  блоки (вложения, память, схемы, виджеты) дописываются как у боевой. «Вернуть боевую» убирает замену.
- Память: агент видит боевую память админа, но писать в неё из песочницы не может (он получает ответ «в песочнице память
  только для чтения»). Экран памяти в песочнице закрыт.

## Подключить

```bash
pnpm add @ykurilov/agent-chat-sandbox
```

Сервер (Hono). Те же настройки чата, что у боевого `createChatHandler`, плюс проверка админа и журнал:

```ts
import { createSandboxHandler } from "@ykurilov/agent-chat-sandbox";
import { createSqliteSandboxJournal } from "@ykurilov/agent-chat-sandbox/sqlite"; // для Postgres: …/postgres, createPostgresSandboxJournal
import { mountChat } from "@ykurilov/agent-chat-server/hono";

const chatOptions = { basePath: "/api/chat", storage, resolveUser, catalog, agent: { instructions, tools } /* … */ };
mountChat(app, createChatHandler(chatOptions));
mountChat(app, createSandboxHandler({
  chat: chatOptions, // тот же объект: агент, инструменты и память те же, что у боевого
  isAdmin: (user) => adminIds.has(user.id), // проверяется на каждом запросе
  journal: await createSqliteSandboxJournal({ filePath: "app.sqlite" }),
}));
```

Next.js: тот же `createSandboxHandler`, файл `app/api/sandbox/[[...path]]/route.ts`:

```ts
import { createNextRouteHandlers } from "@ykurilov/agent-chat-server/next";
export const { GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD } = createNextRouteHandlers(sandboxHandler);
export const dynamic = "force-dynamic";
export const runtime = "nodejs";
```

Страница (React):

```tsx
import { AgentSandbox } from "@ykurilov/agent-chat-sandbox/react";
import { tandemSandboxSkin } from "@ykurilov/agent-chat-skin-tandem/sandbox";

<AgentSandbox skin={tandemSkin} sandboxSkin={tandemSandboxSkin} chatListSkin={tandemSkin}
  chatProps={{ attachments: attachmentsClient, images: imagesClient, videos: videosClient, widgets, diagrams: diagramsClient }} />
```

Адрес по умолчанию `/api/sandbox` (`basePath` у обработчика и у экрана). Пример целиком — `apps/demo` (страница `/sandbox`,
`apps/demo/server/demo-app.ts`).

## Доступ

- Каждый запрос идёт так: проверка источника (`allowedOrigins`) → `resolveUser` → `isAdmin(user, request)`. Не админ получает
  404 на любом адресе песочницы, как будто её нет. Результат не кэшируется: разжалованный админ теряет доступ со
  следующего запроса.
- Песочные чаты лежат в том же хранилище под владельцем `sandbox:<id админа>`. Боевые адреса их не отдают («чат не найден»),
  боевые списки, лимиты и траты их не видят. Чат другого админа тоже «не найден».
- В отчётах приложения песочные траты отделяются функцией `isSandboxOwner(ownerId)`.
- Страница не прячет себя сама: она спрашивает сервер и по 404 показывает «не найдено» (см. `apps/demo/src/sandbox-page.tsx`).

## Журнал

- Хранится в таблицах `sandbox_*`: SQLite (`createSqliteSandboxJournal({ filePath })`, можно тот же файл, что у хранилища
  чата) или PostgreSQL (`createPostgresSandboxJournal({ connectionString })`, схема `agent_chat`). Миграции применяются сами
  при создании. Для тестов есть `createMemorySandboxJournal()`.
- Живёт 30 дней (`retentionDays`). Чистка при старте и раз в сутки; удаление чата удаляет и его журнал.
- Запись не задерживает ответ: события идут через очередь пачками; сбой записи уходит в `logError`, ответ идёт дальше.
- Повторяющееся (инструкция, набор инструментов, история) хранится один раз по хешу и сжатым. Куски больше 256 КБ
  обрезаются с пометкой, картинки и файлы заменяются описанием.
- Секреты не пишутся: заголовки запросов не сохраняются, из всех кусков вычищаются значения переменных окружения с «секретными»
  именами (KEY, TOKEN, SECRET, PASSWORD, PASS, AUTH, CREDENTIAL, PRIVATE) длиной от 8 знаков и пароли внутри адресов
  подключения (`postgres://user:пароль@хост`). Источник — `process.env`, плюс `chat.env` обработчика песочницы (передаётся
  сам, в журнал дублировать не нужно). Свой набор — `env` журнала, явные значения — `secrets`.

## Инструменты агента

Функция `agent.tools(model)` в песочнице получает настоящий id админа в `model.ownerId` (инструмент видит его данные), а чат —
песочный. Если инструменту нужен именно песочный владелец, назовите его в `chatOwnedTools`. По умолчанию так работает
`generate_images`: картинка ложится во вложения песочного владельца, расход пишется на него. Результат инструментов,
который правка ответа менять не должна (файлы), называется в `chat.lockedToolOutputs`; `generate_images` и `show_video`
закрыты всегда.

### Осторожно: инструменты работают по-настоящему

В песочнице инструменты приложения выполняются **по-настоящему и от имени админа**: письма уходят, платежи проходят,
запись идёт в боевую базу. Песочный чат изолирует только переписку, а не мир вокруг. Всё, что нельзя делать «на пробу»,
подмените заглушками, передав песочнице свою копию настроек чата:

```ts
const sandboxChat = {
  ...chatOptions,
  agent: {
    ...chatOptions.agent,
    tools: (model) => ({
      ...chatOptions.agent.tools(model),
      // заглушки вместо опасных инструментов: имя и схема те же, действия нет
      send_email: tool({
        description: "Отправить письмо клиенту",
        inputSchema: z.object({ to: z.string(), subject: z.string(), body: z.string() }),
        execute: async (input) => ({ sent: false, note: "песочница: письмо не отправлено", input }),
      }),
      charge_card: tool({
        description: "Списать оплату",
        inputSchema: z.object({ amount: z.number() }),
        execute: async ({ amount }) => ({ charged: false, note: "песочница: платёж не проведён", amount }),
      }),
    }),
  },
};
mountChat(app, createSandboxHandler({ chat: sandboxChat, isAdmin, journal }));
```

Инструмент, который только читает, можно оставить настоящим: агент увидит реальные данные.

## Лимиты

- Картинки в песочнице считаются на песочного владельца по правилам приложения: если у приложения есть лимит на картинки,
  он применяется к `sandbox:<id>`, если нет — нет.
- У самой модели в песочнице лимита нет, пока приложение не задало свой: `createSandboxHandler({ limits })`. Боевые
  лимиты приложения в песочницу не переходят.
- Траты видны отдельно от боевых: это записи другого владельца.

## Чаты людей

Сотрудник смотрит, что агент ответил человеку, и проверяет, как он ответит теперь. Чат человека только читается: человек
ничего не видит и его чат не меняется.

```ts
createSandboxHandler({
  chat: chatOptions, isAdmin, journal,
  // Поиск человека — функция приложения: Person = { id, name?, hint? }. Без поиска — people: true (id вводят вручную).
  people: { find: async (query) => users.search(query).map((u) => ({ id: u.id, name: u.name, hint: u.email })) },
});
```

```tsx
<AgentSandbox people skin={tandemSkin} sandboxSkin={tandemSandboxSkin} chatListSkin={tandemSkin} />
```

- **Без опции `people`** раздела нет: адреса `/people…` отвечают 404, полосы разделов нет, экран прежний.
- **Чтение.** Админ видит чаты человека (и чаты объектов), историю, как её видит человек, и файлы. Данные объекта не
  показываются. Просмотр ничего не пишет: ни модель чата, ни пометки брошенных ответов (`service.peekHistory`). Поля ввода,
  правки, повтора, кнопок подтверждения и виджетов на экране чтения нет.
- **«Проверить в копии»** делает песочный чат админа с текущей веткой чата человека: даты, картинки, объект чата. Дальше это
  обычный песочный чат: журнал, своя модель и инструкция, правка ответов.
- **В копии** агент читает память человека, но не пишет в неё: инструменты памяти отвечают отказом. Расход и лимиты — на
  админа. Инструменты приложения получают `ownerId` человека и `model.staff = { id }`. **При `model.staff` инструмент не
  пишет в данные человека** — отказывает текстом («В копии чата запись запрещена»); ядро такие записи не перехватывает.
  Пример — `create_task` в `apps/demo/server/demo-task-tools.ts`.
  То же для `afterTurn`: в копии он получает человека, его объект и `turn.staff`; в обычном песочном чате не зовётся.
  Инструменты и хук видят исходный объект чата (`lesson:42` с данными), а не служебный ключ копии.
- **Доступ** — как у всей песочницы: не админ получает 404. Копия называется «Копия: <название чата>», копий одного чата может быть несколько.

Пример — `apps/demo` (`demo-people.ts`, страница `/sandbox`, раздел «Чаты людей»).

## Закрытый чат

Инструмент закрывает песочный чат так же, как боевой (`model.closeChat`): видно, что закрытие работает. Поле ввода гаснет,
над чатом появляется кнопка «Открыть чат снова». Она снимает закрытие (`POST {sandboxBase}/chats/:chatId/reopen`, только
админ, иначе 404), и проверка идёт дальше. Можно и сделать новую копию чата человека: копия всегда открыта. Права приложения
(`chatCapabilities`) и `beforeCreateChat` в песочнице не действуют: там админ.

## Свой вид

- Экран рисуют скины: чат — `ChatSkin` (договор версии 15, новые части необязательные: кнопка «Изменить ответ» и отметки
  «изменено»), песочницу — `SandboxSkin` версии 1 (`SandboxLayout`, `JournalList`, `ModelCallDetails`, `ToolCallDetails`,
  `InstructionEditor`, `AnswerEditor`). Слой поведения решает, что показать и хранит черновики; скин только рисует. Тандем
  готов: `@ykurilov/agent-chat-skin-tandem/sandbox`.
- С `people` у `SandboxSkin` два необязательных слота: `SandboxSections` (переключатель «Песочница / Чаты людей») и
  `PeopleChats` (раздел целиком). Нет их — простой вид; Тандем рисует свои.
- Необязательный слот `ChatReopen` — кнопка «Открыть чат снова» (`onReopen`, `pending`, `error`). Нет — простая кнопка.
  Надписи — поле `chatReopen` словаря (`russianChatReopenLabels`, `englishChatReopenLabels`).
- Надписи — `russianSandboxLabels` и `englishSandboxLabels`, свой словарь через `SandboxLabelsProvider`. Надписи раздела
  «Чаты людей» — поле `peopleChats` словаря (`russianPeopleChatsLabels`, `englishPeopleChatsLabels`).
- `chatProps` — те же возможности чата, что на боевой странице (вложения, картинки, видео, схемы, виджеты, голос). Без них
  агент отвечает, но файлы и картинки в ленте не показываются.

## Безопасность

- Доступ закрыт на сервере, не на странице. Адреса песочницы: журнал, настройки чата, правка ответа и всё, что есть у
  боевого чата.
- Журнал содержит переписку и инструкции, значит читать его может только админ; вычистка секретов защищает ключи
  провайдеров, но не чужие личные данные из разговора.
- С опцией `people` админ читает чаты любого человека приложения: включайте её, только если это разрешено вашими
  правилами о личных данных.
- Запись с чужой страницы отклоняется (403) так же, как у боевого чата.
- Тело запроса песочницы не больше 1 МиБ, инструкция чата не длиннее 100 000 знаков.

## Проверка

`pnpm test:live sandbox` (нужен `OPENROUTER_API_KEY`, `pnpm secrets:load`): демо с настоящей дешёвой моделью, ход с
инструментом, правка ответа и результата, своя инструкция, смена модели, поиск ключа по всему журналу. Стоит около
полцента.
