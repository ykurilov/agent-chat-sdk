# Живые демонстрации в ответах агента

Агент пишет прямо в ответе маленькую интерактивную штуку: ползунок, который двигает график, кнопку, которая считает,
мини-игру. Это блок ` ```html-demo ` с HTML, CSS и JS. Экран запускает его в изолированной рамке во всю ширину ответа.
Отдельного пакета нет: всё в ядре и `@ykurilov/agent-chat-react`.

Без включения блок остаётся обычным кодом, как раньше.

## Включить

```ts
// сервер: одна постоянная строка в инструкции агента
createChatHandler({ …, agent: { instructions: appInstructions, liveDemos: true } });
```

```tsx
// страница (так же у ChatWorkspace и AgentPanel)
<AgentChat … liveDemos />;
```

Строка инструкции (`liveDemosInstructions` из ядра) просит писать демонстрацию блоком ` ```html-demo `, не больше 30 КБ,
без сети, картинки только `data:`, цвета — переменными темы. Она не меняется от хода к ходу, поэтому кэш модели цел.

## Как это работает

- Пока ответ печатается и блок не закрыт, человек видит плашку «Готовлю демонстрацию…». Запускается только закрытый блок.
- Рамка во всю ширину ответа. Высоту демонстрация сообщает сама, рамка не выше 2/3 экрана; дальше — прокрутка внутри.
- Цвета берутся у скина (`ChatSkin.demoColors`) и идут внутрь CSS-переменными: `--bg`, `--surface`, `--text`, `--muted`,
  `--border`, `--accent`, `--on-accent`. Сменил человек тему — демонстрация перезапускается в новых цветах.
- Больше 30 КБ — показан код с пометкой «слишком большая». Ответ оборвался посреди блока — код с пометкой «не дописана».
- После перезагрузки страницы демонстрация запускается снова.
- В песочнице и журнале обращений — код. В мессенджерах вместо блока фраза «Демонстрация доступна на сайте.»
  (`liveDemoOnSite` в фразах бота; пустая строка убирает блок совсем).
- Голосовой режим читает блок как любой код («код на экране»).

## Чат с чужим текстом — демонстрации выключены

Браузер не умеет надёжно запереть любой JS: например, общего запрета WebRTC в CSP нет. Поэтому главная защита —
выключатель. Как только в чат попал чужой текст, ни одна демонстрация в этом чате больше не запускается: показан код
с пометкой «В этом чате есть текст из интернета или файлов…» (`labels.demo.externalContent`, по-английски тоже).

Чужой текст — это:

- итоги веб-инструментов (`web_search`, `read_page`, `page_screenshot`);
- поиск у самого провайдера модели: источники (`source-url`, `source-document`) и вызовы, которые выполнил провайдер
  (`providerExecuted`);
- файл, который приложил человек (свои картинки агента — нет);
- итог любого инструмента приложения с пометкой `metadata: { externalContent: true }`;
- итог помощника или фоновой задачи, которые вызывали такой инструмент.

Пометьте свои инструменты, которые приносят текст со стороны (почта, документы, чужие системы, поиск по сайтам):

```ts
const readMail = tool({
  description: "Читает письмо",
  inputSchema: z.object({ id: z.string() }),
  metadata: { externalContent: true },
  execute: async ({ id }) => mail.read(id),
});
```

Фоновому инструменту (`@ykurilov/agent-chat-background`) — то же поле `metadata`. Модели пометка не уходит: инструкция
и описание инструментов те же байт в байт, кэш модели цел.

Решает сервер. Признак выводится из всех сообщений чата, включая другие ветки. Поэтому он переживает перезагрузку,
сжатие и правку сообщения: раз попал, остаётся. Клиент получает признак в истории (`externalContent: true`) и временным
куском потока `data-external-content`. Кусок приходит сразу после итога такого инструмента, раньше следующего текста.
Если чужой текст уже есть в чате (в любой ветке), кусок идёт в начале хода. Вызовы веб-инструментов, сохранённые до 0.44
(без пометки), узнаются по имени. Без `agent.liveDemos` сервер не отдаёт ни поля, ни куска: приложение без демонстраций
ничего не замечает.

**Импорт (`importChat`).** Импорт переносит только текст и картинки, без вызовов инструментов. Поэтому откуда текст,
служба не знает. Если в переписке был чужой текст (веб, письма, файлы), передайте `chat: { externalContent: true }`:
служба запишет служебную пометку, экран и модель её не видят. Картинки в ответах агента при импорте считаются чужими и
без этого поля, картинки человека — как всегда.

## Безопасность

Код пишет модель, а модель можно подтолкнуть словами человека или чужой страницы. Поэтому код живёт взаперти:

- **Песочница.** `<iframe sandbox="allow-scripts">` без `allow-same-origin`: у демонстрации нет доступа к странице, её
  cookie, хранилищу и входу человека. Нет всплывающих окон, форм, перехода верхнего окна.
- **Сети нет.** Документ со строгим CSP: `default-src 'none'`, скрипты и стили только встроенные, картинки, шрифты и звук
  только `data:`/`blob:`. Ни `fetch`, ни внешних картинок, ни вложенных рамок, ни фоновых потоков (worker). Браузеру
  запрещено заранее искать адреса (`x-dns-prefetch-control: off`).
- **Рамка в рамке — чтобы не увести адрес.** Сам CSP не мешает рамке уйти на чужую страницу (meta refresh, `location`,
  клик по ссылке) и унести данные в адресе. Поэтому внешняя рамка получает промежуточный документ, чей CSP пускает
  вложенные рамки только на `about:`, а код живёт во вложенной. Любой её переход наружу браузер блокирует. Если код
  всё же сменил свою страницу (например, на пустую), демонстрация гаснет и показывается её код с пометкой.
- **WebRTC убран.** Соединение WebRTC (STUN) идёт мимо CSP, поэтому до кода модели `RTCPeerConnection` и родня удаляются.
  Новую рамку со своим WebRTC код создать не может (см. ниже).
- **Без вложенных рамок и заблаговременных соединений.** У вложенной рамки свой WebRTC, а `<link rel=preconnect>` в
  WebKit открывает соединение мимо CSP. Поэтому хост вырезает из разметки демонстрации `iframe`, `frame`, `object`,
  `embed` и `<link>` с `rel` preconnect, prefetch, dns-prefetch, preload, modulepreload, prerender. А свой скрипт до
  кода модели не даёт их создать: `createElement`/`createElementNS` и вставку разметки (`innerHTML`, `outerHTML`,
  `insertAdjacentHTML`, `setHTMLUnsafe`, `document.write`, `createContextualFragment`).
- **Наружу — только высота.** Промежуточный документ пересылает наверх только число высоты и только от своей вложенной
  рамки; страница принимает его только от своей внешней рамки и в разумных пределах. Кликов «в агента» нет: демонстрация
  не пишет в чат и не зовёт инструменты.

Проверено в Chromium и WebKit (`apps/demo/e2e/live-demos-escape.spec.ts`): «злой» сервер не получает ни одного запроса и
пакета STUN ни от одного из приёмов: meta refresh, `location.href/replace/assign`, клик по ссылке, `javascript:`-ссылка,
`</style></head>` с meta refresh, `<base>`, вложенные рамки, `window.open`, форма, `fetch`, картинки, `sendBeacon`,
`WebSocket`, предзагрузка, WebRTC, рамка `srcdoc` со своим скриптом WebRTC (ни одного пакета STUN), `<link
rel=preconnect>` (ни одного TCP-соединения).

**Свои обработчики `message` на странице.** Демонстрация может слать `postMessage` любому окну выше себя; источник у таких
сообщений — `null`. Если у приложения есть свой `addEventListener("message", …)`, проверяйте в нём `event.source` (или
`event.origin`) и не доверяйте данным без проверки.

**CSP вашей страницы.** `srcdoc` наследует политику страницы. Если у страницы `script-src` без `'unsafe-inline'`,
демонстрация не запустится (покажется пустая рамка).

**Что остаётся.**

- **Запрет на уровне страницы не полный.** Браузер не даёт надёжно запереть любой JS. Запрет вложенных рамок закрывает
  найденные пути, но не все мыслимые: например, вставку готовых узлов из другого документа (`DOMParser`, `importNode`).
  Это закрывает выключатель: демонстрация с подсказкой со стороны в чате с чужим текстом не запускается.
- **Непомеченный чужой текст.** Выключатель видит только то, что помечено. Свой инструмент без пометки, текст,
  вставленный человеком в сообщение, заметки памяти из других чатов и импорт без `externalContent` (если в нём нет
  картинок агента) признак не включают. Пометьте инструменты, которые
  приносят текст со стороны.
- **Демонстрация, показанная раньше.** Признак выключает все демонстрации чата, в том числе написанные до чужого текста.

Демонстрация может нарисовать что угодно, в том числе обманчивый текст («перейдите на такой-то сайт»):
ссылки из неё не откроются, но прочитать адрес человек может. Каналы, которые браузер не считает сетью (замеры времени
и т. п.), из рамки наружу данных не выносят: передать их некуда.

## Свой скин

Скин версии 22 в `AgentText` получает необязательный `renderDemo(source, blockIndex)`. Блоки находите той же функцией, что и
слой поведения, чтобы номера совпали: `splitAnswerFences(markdown, { demos: true })` из `@ykurilov/agent-chat-react`.
`renderDemo` возвращает `{ state: "streaming" }`, `{ state: "ready", source, frame }` (готовую рамку — просто поставьте
`frame` в разметку) или `{ state: "code", source, reason }` (`tooLarge`, `unfinished`, `leftPage`, `externalContent` — в чате чужой
текст). Цвета отдаёт
`demoColors(dark)`; нет — берутся запасные. Скин без `renderDemo` показывает блок кодом. Надписи — группа `demo` словаря.
Подробности — [договор v22](skin-v22.md).

Пример — `apps/demo` (сценарии `apps/demo/e2e/live-demos.spec.ts`).
