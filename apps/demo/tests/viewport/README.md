# Keyboard viewport regression

`pnpm exec playwright test --config playwright.viewport.config.ts` from apps/demo runs real ChatWorkspace with Oduvanchik and Tandem, fake HTTP history and emulated VisualViewport geometry. It covers visual-only contraction/pan, both viewports contracting, reader anchoring, draft retention, modal input, pinch, repeated focus and document-style cleanup. This is not a native keyboard test. `VIEWPORT_LEGACY=1` runs the same assertions against the former h-dvh shell; the visual-only test must fail because its height remains 874 instead of 480.

Virtua may emit the browser-generated "ResizeObserver loop completed with undelivered notifications" during initial row measurements, including on the unchanged legacy shell. The test tolerates that known warning, not other page errors. The viewport ResizeObserver queues its writes into the next animation frame.

For a real Safari keyboard on iOS Simulator, run `bash apps/demo/tests/viewport/ios/run.sh` from the repository root through an exclusive GUI runner on iMac. It creates its own iPhone 16 Pro / iOS 26.5 simulator. The first XCTest case loads the fixture to prepare the browser profile; the regression scenarios cover a prepared browser, not factory-first navigation. Native address-bar keyboard input is checked before fixture navigation. Screenshot OCR independently verifies that the Application header stays in place and the typed draft is visible; CSS coordinates alone are not sufficient. The native Blur button must invoke the actual DOM handler. It records the full simulator display and checks draft preservation after closing and reopening. Its simulator and server are removed on exit; other devices are untouched. Xcode and XcodeGen are required. There is no physical-device, iOS Chrome, installed PWA or real Android coverage in this fixture.
