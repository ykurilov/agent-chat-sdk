# Браузерные проверки: что где проверяется

Переделка прогона `pnpm test:e2e`.
Было: 115 тестов, 25,6 мин, один поток, одна общая база. Стало: 34 теста в файлах (43 запуска
с учётом профилей), три этапа, параллельно. Позже замеры скорости вынесены в свою команду, а проверки поведения
идут одним этапом: прогон с 4,6 мин сократился до ~3 мин.

## Как устроен прогон

| Команда | Профиль | Что запускается | Потоки |
|---|---|---|---|
| `pnpm test:e2e` | `timing` | сроки связи 30 ± 2 с, ≤ 45 с, ≤ 75 с, у каждого теста свой сервер | параллельно |
| `pnpm test:e2e` | `iphone-webkit` | `feed`: то, в чём Safari отличается | параллельно |
| `pnpm test:e2e` | `desktop-light` | сценарии 001 и 002 на компьютере, один раз | параллельно |
| `pnpm test:e2e` | `desktop-dark` | `themes.spec.ts`: цвета и снимки тёмной темы | параллельно |
| `pnpm test:e2e` | `iphone-light` | `phone`, `feed`, `liveness-screen`: то, что зависит от экрана телефона | параллельно |
| `pnpm test:e2e:perf` | `perf-phone`, затем `perf-desktop` | `perf-feed`, `perf-latency`, `perf-panel-open`: телефон с процессором ×4, потом компьютер | по одному |

- `pnpm test:e2e` — все проверки поведения сразу, одним этапом, ~3 мин. Профили идут в порядке таблицы:
  первыми — группы с долгими ожиданиями (`timing`, Safari), их ожидание перекрывается остальными тестами.
- `pnpm test:e2e:perf` — замеры скорости, отдельно от проверок поведения, ~1 мин: соседи не шумят.
  Запускать после правок, влияющих на скорость, и в конце этапа.

- Демо раздаётся собранным (`vite build` + `vite preview`).
- У каждого теста свой чат (своё имя пользователя). Тесты с имитацией связи и падением сервера
  поднимают свой сервер и свою базу (`e2e/support/own-server.ts`).
- Настоящее долгое ожидание (70 с раздумья модели) — один тест с пометкой `@long`, только на компьютере.
- Замер «огромный ответ у низа» — в группе замеров (`perf-feed`, телефонный профиль, `pnpm test:e2e:perf`).
- Быстрый набор: `pnpm test:e2e:quick` (только `desktop-light`, без `@long`).

## Убрано и почему

| Что убрано | Причина |
|---|---|
| Все тесты 001 на `desktop-dark`, `iphone-light`, `iphone-dark` (логика: стоп, повторить, ошибки, инструменты, возобновление) | Логика не зависит от темы и экрана; один раз на компьютере. Тема — `themes.spec.ts` (цвета, контраст, снимки). Экран — `phone.spec.ts` |
| Профиль `iphone-dark` | Ничего своего: тема и экран проверяются по отдельности |
| Отдельный тест «стоп на середине» из `us1` | То же самое делает первый тест `us3` (стоп + обновление страницы) |
| Ожидания настоящих сроков в тестах поведения (`liveness`: 30/45/75 с) | Поведение проверяется на коротких сроках (3 с), сроки — модульные тесты на подменённых часах и три замера в `timing.spec.ts` |
| Жёсткие паузы (5 с, 2 с, `networkidle`) | Ждём условия: рост ответа на сервере, появление надписи, часы страницы |
| Ожидание конца минутного «длинного ответа» в тестах ленты и связи | Проверяется рост и целостность ответа, остановка; конец ответа не нужен |

## Требования → где проверяются

«Было» — до переделки (профили `dl` = desktop-light, `dd` = desktop-dark, `il` = iphone-light,
`id` = iphone-dark, `iw` = iphone-webkit). «Стало» — сейчас. «Unit» — модульные тесты, которые
проверяют то же самое (для убранных дублей).
