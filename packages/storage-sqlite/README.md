# @ykurilov/agent-chat-storage-sqlite

Хранилище чатов с агентом на SQLite (Drizzle и `better-sqlite3`).

```ts
import { createSqliteChatStorage } from "@ykurilov/agent-chat-storage-sqlite";

const storage = createSqliteChatStorage({ filePath: "chat.sqlite" });
// …
storage.close(); // при остановке сервера
```

Таблицы создаются и обновляются сами при открытии базы (в том числе колонка `title` для списка чатов: названия старых чатов заполняются по их первому сообщению). Последний выбор модели человека (для новых чатов) лежит в таблице `user_model_choices`. Сообщения не переписываются
задним числом: меняется только ответ, который ещё пишется.

Состояние лимитов расходов лежит в таблице `spending_limit_states` (запись по версии: из двух одновременных записей с одной версией проходит одна; миграция применяется сама).

Идущий ответ отмечается «жив» (колонка `alive_at`, миграция применяется сама), расход помечается «примерно» (колонка `estimated`). SQLite живёт на одной машине с сервером; несколько копий на одной базе и одном компьютере работают так же, как на PostgreSQL.

## Где лежат данные SDK

SDK держит свои таблицы (`chats`, `messages`, `user_model_choices`, `spending_limit_states` и другие) и свой журнал миграций `__agent_chat_migrations` в одном файле. Дайте ему отдельный файл: свои таблицы приложения туда не кладите.

До версии 0.32 журнал SDK лежал в общей таблице drizzle `__drizzle_migrations`. Если приложение вело в том же файле свои миграции drizzle, SDK мог пропустить свои. При первом открытии новой версией записи SDK сами копируются в `__agent_chat_migrations`, уже применённые миграции не повторяются. Пропущенные миграции SDK применяются, даже если они в середине, а более поздние уже прошли: SDK сверяет каждую миграцию по своему журналу, а не только последнюю. Общая таблица остаётся как была.

При открытии, до миграций, SDK проверяет файл. Если в нём есть `chats` или `messages`, а журнал миграций SDK их не знает, значит таблицы чужие. Тогда `createSqliteChatStorage` бросает `ForeignChatTablesError` («дайте SDK отдельный файл»), закрывает файл и ничего в нём не меняет. Таблицы не переименованы, чтобы не ломать уже работающие базы. В PostgreSQL SDK живёт в своей схеме `agent_chat`, там чужим таблицам места нет.

`better-sqlite3` приходит с готовыми сборками (macOS, Windows, Linux, в том числе Alpine): собирать ничего не нужно.
pnpm 10 напишет «Ignored build scripts» — это можно не трогать. Разрешать сборку
(`onlyBuiltDependencies: [better-sqlite3]` в `pnpm-workspace.yaml`) нужно, только если у вашей платформы готовой сборки нет.

Подключение целиком: [docs/getting-started.md](https://github.com/ykurilov/agent-chat-sdk/blob/main/docs/getting-started.md).

Журнал изменений и что делать при обновлении: [CHANGELOG.md](./CHANGELOG.md). Все пакеты SDK выходят вместе и с одной версией; обновление — `pnpm update "@ykurilov/agent-chat-*" --latest`.
