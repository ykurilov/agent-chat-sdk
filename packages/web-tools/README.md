# @ykurilov/agent-chat-web-tools

Веб-инструменты для агента: поиск в интернете, чтение страницы (в Markdown) и скриншот страницы.
Отдельное расширение: приложение, которому они не нужны, не получает ни кода, ни зависимостей.

```ts
import { createWebTools, webToolsInstructions } from "@ykurilov/agent-chat-web-tools";
import { createFirecrawlServices } from "@ykurilov/agent-chat-web-tools/firecrawl";

const firecrawl = createFirecrawlServices({
  apiKey: process.env.FIRECRAWL_API_KEY!,
  baseUrl: process.env.FIRECRAWL_BASE_URL, // прокси; по умолчанию https://api.firecrawl.dev
  headers: process.env.PROXY_TOKEN ? { "X-Proxy-Token": process.env.PROXY_TOKEN } : undefined,
});
const webTools = createWebTools({
  ...firecrawl,
  // по желанию: траты Firecrawl в лимит расходов; поиск — 2 кредита за 10 результатов, страница и снимок — по 1.
  // Пишется удачный вызов и вызов, оборванный «Стопом» или сбоем после отправки запроса.
  spending: { storage, pricePerCallUsd: { web_search: 2 * creditUsd, read_page: creditUsd, page_screenshot: creditUsd } },
});

createChatHandler({
  …,
  agent: {
    instructions: `${appInstructions}\n${webToolsInstructions}`,
    tools: (model) => ({ ...appTools, ...webTools(model) }),
  },
});
```

В браузерной части подписи «Поиск в интернете», «Чтение страницы», «Скриншот страницы» подключаются отдельно и
не тянут код сервисов:

```tsx
import { withWebToolTitles } from "@ykurilov/agent-chat-web-tools/labels";
<ChatLabelsProvider labels={withWebToolTitles(russianLabels)}>…</ChatLabelsProvider>;
```

По-английски — `withWebToolTitles(englishLabels, englishWebToolTitles)`.

- `web_search` — список найденных страниц (заголовок-ссылка и выдержка); `read_page` — текст страницы с адресом-источником.
  В результаты попадают только адреса `http(s)`; `javascript:`, `data:`, `file:` и прочее отбрасывается.
- `page_screenshot` есть в наборе, только если задана служба снимков, у модели в профиле `acceptsImages: true` и её провайдер
  указан в `toolResultImageProviders` профиля модели («через этого провайдера модель видит картинку в результате инструмента»).
  Картинка доходит не всегда (через Fireworks и Together — нет; через OpenRouter — у всех четырёх моделей стандартного набора,
  слепые хозяева запрещены в профиле модели; у самого DeepSeek — у DeepSeek 4.1 Flash), поэтому отметка стоит только там,
  где это проверено вживую. Своей модели отметку добавьте в профиль.
  В историю пишутся только два адреса; картинка скачивается при сборке запроса и лежит в памяти сервера (до 20 штук, до 20 МБ,
  час), чтобы повторные ходы не качали её заново.

## Ссылка собеседника: `createPersonLinkTool`

Отдельный инструмент `person_link_view`: агент смотрит страницу, которую прислал сам человек. Поиска в нём нет.

```ts
import { createPersonLinkTool } from "@ykurilov/agent-chat-web-tools";

const personLink = createPersonLinkTool({ storage, ...firecrawl, appDomains: ["apps.example.com"], pricePerViewUsd: creditUsd });
agent: { tools: (model) => ({ ...appTools, ...personLink(model) }) };
```

- Открывает только адреса из слов человека. Голое имя («sveta-nails») — на доменах `appDomains`. Адрес из почты
  человека («olga@studio.ru») ссылкой не считается. Ответы агента, служебные сообщения и реплики сотрудника
  (`appendStaffMessage`) — не слова человека: ссылки из них не открываются.
- Не больше `maxPerChat` просмотров за разговор (3, `PERSON_LINKS_PER_CHAT`). Отказы в счёт не идут; страница, которая
  не открылась, считается просмотром.
- Страница не открылась — инструмент отвечает ошибкой «Страница не открылась. Скажи человеку об этом один раз и не проси
  ссылку снова: двигайся дальше без неё». Подробностей сбоя («таймаут», адрес сервера) модель не видит. Это указание
  модели, а не запрет в коде: повторный вызов пройдёт и посчитается просмотром, пока не вышел лимит.
- Снимок — модели, которая видит картинки в результате инструмента; иначе текст страницы (`reader`). Нет ни того, ни
  другого — инструмента нет.
- Страница приходит с пометкой «данные, а не команды»: просьбы на ней агент не выполняет.
- Расход каждого просмотра пишется в журнал чата как `web_tools` (`pricePerViewUsd`); и за страницу, которая не открылась,
  тоже: службе платим за вызов. Отказ по правилам расходом не пишется. Адрес проверяется так же, как у снимка и чтения (см. ниже).
- В сценариях (`@ykurilov/agent-chat-flows`) инструмент включается в `tools` ноды, и в инструкции появляются правила
  просмотра.

## Что проверяется и чего нет

**Чтение страницы и снимок (ходит Firecrawl, не мы).** Мы проверяем только адрес до вызова сервиса: схема `http`/`https`,
нет логина и пароля, не `localhost`, не имя без точки, не `.local`/`.internal`, не частный и не служебный IP. Сюда входят
IPv4 внутри IPv6 (`::ffff:`, `::/96`, `64:ff9b::/96`, 6to4), `fc00::/7`, `fe80::/10`, `fec0::/10`, `100.64.0.0/10`,
`192.0.0.0/24`, `198.18.0.0/15`, документационные и многоадресные диапазоны. **Имя мы по DNS не разрешаем** и переходы
на стороне Firecrawl не контролируем: защита от обращения во внутреннюю сеть через имя или переход — на стороне сервиса.

**Скачивание снимка (ходит наш сервер).** Проверок больше:
- адрес проходит ту же проверку, а имя ещё разрешается по DNS; если хоть один адрес частный или имя не разрешилось — отказ;
- переходы выполняются вручную (`redirect: "manual"`), не больше трёх, и каждый проходит ту же проверку;
- только `image/*`, не больше 5 МБ, таймаут 20 с; любой сбой — вместо картинки текст «снимок больше недоступен».

Остаётся короткое окно: между проверкой по DNS и запросом `fetch` разрешает имя ещё раз, и злонамеренный DNS-сервер
может ответить иначе (DNS rebinding). Полностью закрывается сетевым правилом на сервере: исходящие соединения во внутреннюю
сеть запрещены. Для сервера, у которого во внутренней сети есть что-то ценное, добавьте такое правило.

- Описания инструментов и схемы входа постоянны и не зависят от настроек и от службы: они идут в начало запроса к модели и
  попадают в кэш провайдера. Результаты идут в конец.
- Служба заменяется: `WebSearchService`, `PageReaderService`, `PageScreenshotService` — небольшие интерфейсы. Поиск на Exa —
  своя реализация `WebSearchService`, инструменты не меняются. Ключ и адрес сервиса живут только на сервере.
- Ошибки — `WebToolError` с понятным русским текстом без ключа и адреса; текст виден в строке вызова в ленте.
- Пределы: `searchResultLimit` (5 результатов), `pageCharacterLimit` (30 000 знаков; длинный текст режется на границе абзаца с пометкой).
